# 作物与田地动画

下述项目路径以仓库根目录为基准。先读 `AGENTS.md`、`docs/development.md` 的作物成长动画段落，以及本次涉及的 `docs/expansion/05-catalog.md` 和 `docs/expansion/06-research.md`。新增作物先编辑式样再生成运行数据，保持旧 ID、BigInt 经济及存档兼容。

新增或重画时读取 [交付清单](references/delivery.md)，核对每个目录 `kind: C` ID 的图标、独立设施场景和四期动画。除 C01 已认可例外外，树和苗必须交付独立单株文件，运行时每个根位各建一个 Sprite，可共享同阶段纹理；整田合成图不能代替这项交付。

遵循 `scripts/export-crop-animation.mjs`、`assets/plot/crop-layout.json` 与 `src/content/crop-visuals.json` 的真实单株导出链。四期共用同一组固定根位，按真实 ground 原田垄和统一透视列覆盖完整可种范围，每排都有作物，不能只在两列窄条种植或用跨排贪心间距筛掉整排。近大远小，前排整株可遮住洒水器和水花。成长期和成熟期保留该品种整株特征，收获物画在植株上。**C01 沿用 `assets/plot/wheat/wheat-0.png` 至 `wheat-3.png` 的已确认整幅前景与旧图集**，不改原麦、不虚构 C01 单株目录。

已有真实四期单株原画可以复用，布局调整和格式转换不要求重画。只有新增或真正改画源图时才使用 `imagegen` 技能调用内置工具。保留源图和裁切依据；若替换种子／幼苗原画，同步实际读取路径，不能只存新图却仍发布旧的自动生成图。Python 兼容入口现已转发同一 Node 单株导出链，不另建 Pillow 整田回退，也不能恢复已淘汰的 C02 起整田运行前景。

生成交付后，将精确版本的源图、对应 PNG／WebP 与用途证据交 [farm-art-review](../farm-art-review/SKILL.md) 验收。证据不足记待复查；实证不合格交素材所有者用 `imagegen` 重画／修订，再审新版本。技术门禁通过不代表视觉通过。

展示周期取实际生长时间与 5 秒的较大值，均分种子、幼苗、成长、成熟四期。成熟末尾作物层 300ms smoothstep 淡出，留空 30ms 再到种子；短批次保留展示相位，实际收获与任务统计按经营逻辑结算。

仅为可见的活跃地块创建动画，按需加载、最近邻绘制；滚出、弹窗、切页、后台时卸载。失败使用同 ID 独立设施场景，保持单画布命中，不恢复已删除的减弱动态。源图／静态布植交接图、运行逐根 Sprite 和实际画布验收分别记录；本轮大型漏排、对齐与铺满的旧完成结论已撤销，不能因改为单株或交接图存在便结案。后续再次报告时同样重开，并将实际证据和限制写入持久反馈。

遵守项目验证授权：本技能不授权测试、预览、`--check` 或试编译。未取得用户明确授权时不执行这些操作；全部资源和模块完成后仅由主管执行最终构建。推送另需当前任务的明确指示。
