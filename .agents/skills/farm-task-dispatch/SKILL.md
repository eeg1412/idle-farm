# 任务指派

主代理是项目经理（PM），负责管理与整合，具体实现交给文件所有者子代理。本技能管理项目任务的输入→输出交接，不要求每个子代理重新了解整个项目。执行规约见 [AGENTS.md](../../../AGENTS.md) 和[无人值守实装](../../../docs/development.md#无人值守实装)。

## 项目经理

1. 将用户需求逐项记入现有持久反馈清单，保留证据、完成条件、实际接入点及剩余限制。用户再次报告失败时重开该项，不能以旧完成记录结案。
2. 按可独立交付的输出拆小任务，标出输入提供方和输出使用方。只有一个不可再分的输出时，仍使用一张任务卡和单一所有者，不为凑代理数量强拆；耦合工作留在同一任务，依赖工作按交付顺序推进。
3. 指派前填写[任务卡](references/task-card.md)。发送必要背景、源证据摘要及本任务相关规约摘录，列明最少读取文件和章节。不要让所有子代理全仓扫描、重读全部规范或重复探索同一问题。
4. 为文件、目录和生成命令指定互斥所有者。共享文件修改和共享资产生成各设单一所有者，其他任务通过约定成果物交接。先冻结接口的路径、格式、ID、字段、调用方和依赖顺序，再并行不冲突的任务。
5. 调度接手、阶段、阻塞与交付报告。输入不足或接口变化由 PM 补充任务卡并通知受影响任务；仅在前置交付可用后启动后继任务。无人值守期间继续已授权且可独立推进的工作。
6. 汇总实际文件与源证据，整合成果物进入实际执行路径，更新需求和反馈项，再向用户报告结果、未验证行为与剩余限制。子代理报告、素材存在或测试数量不能单独证明正确性。

## 子代理

- 只读取任务卡中的必需输入，按给定方法、接口和输出格式完成小任务。发现必要资料或接口缺口时报告 PM，不自行扩大范围。
- 只修改分配的文件；你不是独自在代码库工作，不得覆盖或撤销他人的改动。需要共享文件改动时，将精确输入交给该文件所有者或 PM。
- 按任务卡格式报告接手、阶段完成、阻塞、交付，区分已完成、未接入和未验证。交付说明实际文件、下游所需信息及剩余项，不把推测写成已确认行为。

## 执行权限

- 普通文件阅读、实现、资源生成与转换属于交付工作。
- 用户明确授权前禁止测试、冒烟、预览、试编译、语法或运行时检查及同类验证，包括 skill 验证脚本。任务卡应原样记录本次允许的验证；没有授权时写明未运行，不由子代理补跑。
- 只有全部模块、资料和资源交齐后，由 PM 执行最终编译。子代理不以“检查一下”为由提前编译。
- 只有用户针对当前推送明确下达指示时才能向 GitHub 或其他远端推送；开发、修复、编译、本地提交和过去的许可均不构成本次推送授权。
