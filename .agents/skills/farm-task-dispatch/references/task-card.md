# 指派任务卡

由项目经理填写后随指派发送。每张卡只描述一个独立输出；不适用项明确写“无”，禁止留给子代理重新探索全项目。

## 基本信息与目标

- 任务 ID / 负责人 / 当前阶段：
- 需求或持久反馈项：
- 用户背景、目标及需要解决的具体问题：
- 本次输出和完成条件：
- 输入提供方 / 输出使用方：

## 上下文选择与最小交接

- 上下文相关性：列明与拟复用代理目标及成果物的关系，属于同一目标、连续成果物或直接依赖链中的哪一种；无关则明确写“无关”。
- 分派选择：复用现有代理及具体理由，或新建干净上下文（`fork_turns: "none"`）。相同文件、同种工具、空闲或熟悉项目不单独构成复用理由；连续微步骤不机械另建代理。
- agent↔objective↔artifact：代理名称、负责目标、实际成果物路径及当前所有权状态。
- 最小交接：仅列接手目标、必需事实及证据位置、成果物与版本、冻结接口、剩余问题、授权范围和所有权状态；不传无关任务的旧对话。
- 槽位与接续：槽位不足时排队或结束已完成任务释放槽位，不把无关任务串入旧代理；无需安排时写“无”。

## 精确输入与证据

- 已提供输入：路径、稳定 ID、版本或已有接口，以及源证据位置。
- 已确认事实：附必要摘要；保留来源，区分事实、用户明确提出的额外行为和未知项。
- 最少读取：逐项列出文件及章节；说明每项用于哪个决策。不要写“先熟悉整个项目”。
- 相关 AI 开发规约：只摘录本任务适用的内容，并列出文件及章节出处；涉及专门 skill 时给出入口及本次必读 reference。
- 规格或资料缺口：列明待 PM 补充的输入，不自行虚构。

## 所有权与执行边界

- 可编辑：精确文件路径或不会与其他任务重叠的目录。
- 禁止修改：共享文件、其他任务输出和本次无关范围。
- 共享文件 / 共享资产生成所有者：
- 所有权转交：旧所有者及明确结束状态、新所有者及接手时点、交接成果物和未完成项；须先结束旧所有权，再开始新所有权，无转交时写“无”。
- 你不是独自在代码库工作，不得覆盖或撤销他人改动；范围或接口需要改变时先向 PM 报告。

## 方法、接口与依赖

- 怎么做：给出实现所需步骤或关键决策依据，不重复项目通用教程。
- 冻结接口：输入输出路径、格式、ID/字段、调用方或导出入口；不适用时写“无”。
- 前置依赖及可开始条件：
- 下游交接及先后顺序：
- 允许并行的工作 / 必须等待的工作：

## 成果物与完成条件

- 成果物路径和格式：列出每项实际文件及用途，明确源文件、生成文件和下游接入资料的责任人。
- 完成条件：逐项对应需求；区分本任务交付完成、实际执行路径接入和行为确认。
- 交付给 PM：变更文件、输入→输出对应、接口说明、证据、未完成项及限制。

## 允许验证与未验证项

- 本次用户已明确允许的验证及授权范围：没有时写“无”。
- 禁止未授权的测试、冒烟、预览、试编译、语法或运行时检查及同类验证；普通读写和资源生成允许。
- 子代理不运行最终编译；全部模块、资料与资源完成后由 PM 执行。
- 未验证项及原因：不得以素材存在、报告或测试数量替代实际正确性。
- 本次推送授权：没有用户针对当前推送的明确指示时写“无”，不得推送。

## 汇报格式

- 接手：任务 ID；上下文选择及理由；agent↔objective↔artifact；已收到输入；拥有的文件；下一步；缺失输入。
- 阶段完成：已产出文件；接口或依赖变化；剩余工作。
- 阻塞：阻塞事实与证据；所需输入或 PM 决策；仍可独立推进的部分。
- 交付：实际文件及格式；需求对应；下游最小交接；所有权结束或转交状态；未接入/未验证/未完成项；本次实际运行的已授权验证（未运行则明确写明）。
