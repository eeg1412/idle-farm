# 牲畜与畜牧动画

下述项目路径以仓库根目录为基准。先读 `AGENTS.md`、`docs/development.md` 的畜牧动画段落，以及本次涉及的 `docs/expansion/02-livestock-fish.md`、`docs/expansion/05-catalog.md`、`docs/expansion/06-research.md`。新增 ID 先更新式样和生成数据，保留旧 ID、BigInt 经济与旧档兼容。

新增或重画时读取 [交付清单](references/delivery.md)，按稳定 ID 逐项交付。**活牲畜选择图与产出物品图是不同资源；动画产物和仓库共用同一张 `public/wiki/icons/<ID>.webp`**，不另画或另交动画产品图。不能用鸡蛋、肉、奶或缩小的棚舍场景代替牲畜选择图。

已有物品图默认复用；任务卡明确授权单项变更时，更新 canonical 图的持久来源及常规导出链，不能只覆盖 `public/` 成品或扩大到其他产物。仓库与动画仍消费同一文件。

按任务卡提供的最新用户画风约束、资源范围与阶段门执行，当前进展查阅 `docs/feedback-checklist.md`。用户明确要求先审样稿时，先交指定样稿，未确认不批量生成或覆盖正式资源；确认后由 PM 更新反馈及后续任务卡，继续已授权工作，不重复申请已有授权。

以 `assets/livestock/layout.json` 的显式 `slaughter` 和阶段登记为视觉依据，生成 `src/content/livestock-visuals.json`。覆盖目录所有 `kind: L` 品项，不用 ID 前缀、序号范围或固定名单猜测肉用分类。每期四帧均为真实低头啄食／咀嚼动作，头颈变化画在原图中，躯干和站立脚点稳定，不能旋转、缩放整只动物假装进食。使用 `imagegen` 绘图技能调用内置 `image_gen` 生成新原画，由一个素材负责人独占共享原画与导出；脚本只裁切、归一网格、按固定脚位打包并导出。

动物原画不含饲料、食槽和地面投影。每阶段显式 `feeding` 保留低头口部对应的地面饲料位置和 grain／hay／greens 来源类型。每只动物独立显示共用透明复合饲料图片与各自轻影，按相同站位变换保持近大远小；不新增手动喂养动作或经济消耗。用户再次否定 v6-r3 黄料堆后，当前 V8 由内置 image_gen 新画深蓝灰低沿托盘、米白谷粒／棕颗粒／绿色草料大分组，目的是与金黄地板拉开轮廓和明暗差；托盘仅为图片组成，不增加设施或喂养玩法。原稿、提示词与生产登记见 `assets/livestock/feed-registration-v8.json`。运行接口仍为 `textures.feed` 与每 ID 的 `feedTexture`，运行／静态回退共用 `livestockFeedLayout`，低头时也须露出可辨主体。保留 V5 80 帧、真实脚嘴登记与 V7 选择图，不用挪动物／脚点来迁就料盘。旧版内部静态通过已被用户新反馈重新打开，不能当用户接受。

活牲畜选择图恢复普通抬头展示。用户明确否定 V4 复用后，当前全部 10 种必须逐 ID 输入其当前 V5 成熟动画 PNG 的第 0／3 帧，由内置 image_gen 新生成同一动物的中性抬头图；毛色、脸型、角耳、体型比例和像素细节均按实际当前帧，不用旧风格稿替代指定输入，也不旋转／缩放低头动物冒充新图。持久来源为 `assets/livestock/choice-registration-v7.json`，逐 ID 保留真实输入路径／哈希、新原稿、提示词与转换；V4 批仅在 `choice-v6-rejected/` 和旧登记保留历史。普通生产与 `--choices-only` 都消费 V7 新原稿，不能回退为 V4 或 V5 低头首帧。进食 80 帧及图集来源仍由 `feeding-registration-v5.json` 管理；选择和饲料使用独立生产路径，饲料重设计不得覆盖已交 V7 选择图。

生成交付后，将精确版本的源图、对应 PNG／WebP 与用途证据交 [farm-art-review](../farm-art-review/SKILL.md) 验收。证据不足记待复查；实证不合格交素材所有者用 `imagegen` 重画／修订，再审新版本。技术门禁通过不代表视觉通过。

动物原画不含地面投影，原物品图也不烘焙程序阴影。PixiJS 分别为动物和全部产物绘制独立椭圆地面影：动物影按各阶段真实站立脚印登记，不能移动动物帧迁就影子；肉品按成熟阶段落脚点接地并跨收获淡出保持位置，其他产物在动物附近接地。同一阶段四帧沿用同一尺度与固定解剖脚点，不逐帧按 bbox 重居中，也不用加权脚底像素中心补偿位置。资源负责人须交付共享尺度／锚点、`grounding` 与原物品内容 bounds，运行时分别按动物／产物透明度控制阴影；尺寸和阴影 Alpha 按当前任务卡的实现选择，不写成用户已确认的固定数值。完整接口见[交付清单](references/delivery.md#落地阴影与帧稳定性交接)。四帧齐全或元数据有效不能证明动画连贯、不抖，仍须记录真实源图／分镜与实际运行的验收状态。

每个阶段显式登记 `supportBandHeight`、脚部材质 `supportMaterial` 和 `supportXRange`，按真实支撑脚区排除低头的嘴／喙，不能让进食姿态污染动物脚印阴影。导出只消费登记，不按固定牲畜 ID 名单推断脚印或补默认值；`productCell` 仅为可选历史字段，不是新增动物必交项。

低头嘴／喙真实低于脚线时，只能以可追溯的 `feedingSource.mouthBounds/sourceMouthBounds` 作紧凑局部登记，不能把头前整片地面或支撑脚区列为豁免。脚线只看显式脚区，全幅疑似烘焙投影仍拒绝；QA 必须看最新红框分镜，元数据或技术门禁不能代替局部区域的实际审图。修正脚点后同步重导并审新版本，不能沿用旧静态证据。

牲畜采用兼顾像素边缘和形体细节的像素精灵：用可辨认的色块、阶梯轮廓和离散明暗表现清楚的五官、羽毛分组／毛团及身体结构，避免细碎写实毛发、柔光或拟真体积，也不能简化成缺少特征的粗块图。不能把被否定的拟真图降采样或加像素化滤镜称作重画。透明选择图、全部 idle 帧及同 ID 静态回退中的动物须保持同一画风；库存产出图是否重绘按任务卡范围执行。详细源图、手机图块尺寸与放大边缘审核规则见[交付清单的画风要求](references/delivery.md#像素精灵画风与重绘)。

展示周期跟随真实批次时长，无保底，短批次三档（每阶段至少 1 秒）：真实时长够全部阶段加 1 秒时完整播放，只够首末两阶段加 1 秒时只播首、末阶段，再不够只显示最后阶段；附属产品类保持成年动物，肉类使用幼年、成长、成熟三期。每期四张独立 idle 原画，每帧 300 毫秒。产品在展示收获前 3 秒（末阶段不足 3 秒时为整个末阶段）淡入，肉用动物同期淡出；收获后产品淡出。淡变都是 300 毫秒 smoothstep。实际生产和任务统计不跟随展示循环。

UI 继续使用 PixiJS 单画布。按可见性加载和卸载，使用最近邻贴图和同 ID 静态回退，不恢复已删除的减弱动态功能。提示词含 `pixel-art`、素材数量／哈希、像素化滤镜、资源存在或旧构建通过都不能证明画风合格或选择图可辨识；用户否定后须重新打开持久反馈，记录实际交付和未验收项，不能把内部判断写成用户已接受。

遵守项目验证授权：本技能不授权测试、预览、`--check` 或试编译。未取得用户明确授权时不执行这些操作；全部资源和模块完成后仅由主管执行最终构建。推送另需当前任务的明确指示。
