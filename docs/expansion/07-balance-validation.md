## 7.1 目录输入与生成

`src/content/game-data.json` 的格式版本为 1.14，经济版本为 LT-2026-11-v13。1.14 快照 `src/content/balance-baseline-v114.json` 用于锁定已有 ID、生产配方和数量、来源、商品等级、研发前置和耗材种类。[物品表](05-catalog.md) 的基础周期下界首版按 v6 的无科技运行周期冻结，后续逐项在 05 维护。[研发表](06-research.md) 声明前置和耗材 ID，[养殖表](02-livestock-fish.md) 补充养殖对象名。生成无需前一次运行目录。

新增品项时先追加上述式样行与品类计数，商品还需在 [08](08-crop-uses.md) 登记类别等级。在生成前校验未知 ID、无效数量、配方来源、生产和研发拓扑及快照结构。每次重读全表，先算品项消耗量，再重算所有批量、周期、工时、售价、研发报价和目录相关任务上限。新增配方可改变其投入物和受影响产线的运行目录。公式及输入校验全部成功后写出 `src/content/game-data.json` 与 `src/content/task-coin-caps.json`。

### 新增品项周期差

使用生成后的无科技单批基础耗时 `durationMs`（`t × 1000`）。新增品项须与全目录其他品项比较，涵盖跨品类、与既有品项配对及新增品项之间的配对。只有双方都属于规则生效时冻结的 525 个既有 ID 的配对豁免，豁免名单固定。

两项耗时绝对差须大于 10,000 毫秒，恰差 10 秒也冲突。例如新增项 50 秒，与既有 F01 鲫鱼 42 秒相差 8 秒，生成失败。05 的 `s` 是周期下界，配方按 §7.3 得到 `t` 后再校验。

`npm run content:generate` 与 `npm run content:check` 均自动执行此校验，冲突在写出产物前报错并中止。优先修订参与冲突的新配方下界。新增用量跨档引起既有品项间的周期冲突时，在版本记录中说明受影响品项、最小可用下界及生成结果，继续执行同一周期差门槛。

## 7.2 批量、含料工时与售价

| 值 | 算法 |
| --- | --- |
| 用量 `Uⱼ` | 每条生产配方消耗 j 的件数求和。每配方计一次 |
| 基础批量 `Qⱼ` | `1+isqrt(floor(Uⱼ/2))`。未被消耗为 1，用量达到 `2k²` 即至少 `k+1` 件 |
| 周期下界 `sⱼ` | 05 表的正整数秒，范围 1–43,200 |
| 基础周期 `tⱼ` | 原料为 `sⱼ`。配方按 §7.3 |
| 分摊工时 `Aⱼ` | `Σᵢ qᵢⱼ·Hᵢ/Qᵢ`，其中 `qᵢⱼ` 为单批直接投入。原料为 0 |
| 含料工时 `Hⱼ` | `tⱼ+Aⱼ`，单位秒 |
| 基准目标率 `R(H)` | `1+H/3`，用于确定周期与基准币值 |
| 全局金币倍率 `m` | `src/content/economy-scale.json` 的正安全整数 `coinScale`，当前为 5，对应理论批价 ×50 |
| 基价 `pⱼ` | `floor(m·tⱼ·R(Hⱼ)/Qⱼ)`，低于 10 金拒绝生成 |
| 实际产值率 `rⱼ` | `pⱼ·Qⱼ/tⱼ` |

周期、工时、定价、研发及验收使用约分的 BigInt 有理数或等价整数比较。按 H 分组，相邻组中较高工时的最小实际率须大于较低工时的最大实际率。同 H 的实际率可有单价取整差。品质、科技及设施倍率按 [经营规则](01-operations.md) 独立应用。

## 7.3 配方定价

沿生产拓扑选满足全部条件的最小整秒 `t`。确定周期时使用基准目标率，所以改变全局金币倍率不改变周期或批量。

1. `t≥sⱼ`。对每个直接输入 i 同时满足 `10t≥11tᵢ` 与 `10tQᵢ≥11qᵢⱼtᵢ`。
2. `R(t+Aⱼ)−Qⱼ/t ≥ (11/10)·ΣᵢR(Hᵢ)`。左侧随 t 严格递增，生成器在第 1 条下界到 43,200 秒间整数二分。43,200 秒仍不满足的项报告品项和门槛。
3. 使用 §7.2 单价式。出表前验 `pⱼQⱼ≥1.2·Σᵢqᵢⱼpᵢ`，且 `rⱼ>1.1·Σᵢrᵢ`。同窗比较取每种直接投入各一座满速专用上游的全部产值，包含未消耗的余量。

以下为 v10 历史计算样例。当前派生值以运行目录为准。

| 品项 | U | Q | t（秒） | H（秒） | 基价 | 金/秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| C01 小麦 | 2 | 2 | 12 | 12 | 150 | 25 |
| C05 苹果 | 2 | 2 | 29 | 29 | 773 | 53.31 |
| F01 鲫鱼 | 2 | 2 | 42 | 42 | 1,575 | 75 |
| I01 面粉 | 258 | 12 | 14 | 26 | 56 | 48 |
| IF01 鲫鱼鱼糜 | 31 | 4 | 93 | 135 | 5,347 | 229.98 |
| P01 乡村面包 | 0 | 1 | 31 | 106/3 | 1,980 | 63.87 |

面包摊入 `2/12×26` 秒面粉工时。焦糖饼干 P02 最短 64 秒，实际产值约 122.36 金/秒。品质 1、设施与工位 1 级、经营改良 0 级为以上口径。品质及市场行情会改变现行机会增值，运行时应按投入和产物各自的成交价实算。

## 7.4 研发生成规则

按研发前置拓扑生成。对每项 j，令 S 为 [06](06-research.md) 的材料 ID 集合，`M₀=Σᵢ∈S pᵢ`。

1. `B=ceil(m·(30+Hⱼ/2)·R(Hⱼ))`。目标总价 `T` 取 `B`、`ceil(5M₀/2)`、`M₀+10m`、有研发报价的工坊前置各自 T 的最大值。
2. 每种先给一件。把 `max(0,floor(T/3)−M₀)` 平均分到各材料，按单价向下取整为额外件数。每种总件数最多 `max(1,floor(D·Qᵢ/tᵢ))`，`D=max(300,min(3600,ceil(Hⱼ)))` 秒。若公式上限为零仍保底一件并输出诊断。材料空表跳过分配。
3. 以基价合计实际材料现值 M，未打折金币为 `T−M`。校验金币为正、`5M≤2T` 及工坊前置总价不超过依赖项。原研究材料降费科技仅作用于运行实物数量。

报价示例包括 C02 的 942 金、1 小麦、2 面粉，P01 的 2,148 金、3 小麦、8 面粉，以及 F01 的 2,625 金、8 小麦。P169 完整报价 678,292,149。当前生成结果中，单件保底超过 D 的条目是 C58→P161 和 P169→P168，仍须准备库存。

## 7.5 静态与事务核对条件

- 运行 `npm run content:generate`、`npm run content:check`、`python3 scripts/validate-expansion-spec.py` 和 `npm run balance:check`。用 `node scripts/generate-game-data.mjs --check --details` 查看逐项 U、Q、s、t、A、H、基价、实际率、供料下界及同窗目标。
- 复算 574 项、476 条配方与 572 项研发，并核对计算样例、上下游分摊、收益严格排序、批量、最低价格、同窗、加工增值以及研发比例。两次生成两份产物须逐字节相同。追加会跨 U 档的配方验证各受影响派生值随之重算。v13 有 107 条配方实际周期高于下界，最长单批为 15,246 秒。
- 任务奖金用生成的未取两位有效数字整数上限与 [任务规格](01-operations.md#15-任务金额与存档)。品质任务用 `100×m×目标抽数` 生成直接金币奖励。检查首出货只发金币、不发高级点，领取记录与结算同事务，导入与失败保存均不发奖。
- 验证加权整点、品质单抽与全抽等价、保存原子性、逐项科技上限、过时出货报价、同刻扣料与取消退款、正式／开发隔离与同一存档结构跨目录导入。核对既有批次的产量、投入、起止时刻，设施升级按已存快照重算，续批按目录基础批量和有效倍率开批。离线 6／12／24／48／72 小时用实际供料确认等有效时间下的在线／离线等价。

## 7.6 经营效果与实际限制

以下专线容量与时间是 v10 历史记录。专线以每种输入 `qᵢⱼ+Qᵢ` 的可消费库存预热，同刻先完工入库再扣料。共享排产按实际件数与当前周期汇总，各投入应满足至少 10% 供给余量。预建设施、无抢料且有可消费缓冲时，专线首件上界为 24,934 秒。单产物专用供料树最大设施数按农业、畜牧、水产、加工、精制分别为 20、8、9、27、1。开工准备、设施购建与共享库存影响实际等待。

从新档以真实投入重放首面包、首畜牧、首鱼及首复合商品，分别验 5、10、10、45 分钟上限。长线部分是满级测时工具，测量满级需要多久，不以天数判定通过。它按每日一次、每日两次、每三天一次的回访策略（`--visit=`，默认 `1,0.5,3`），以有限资金、设施、库存、回访时间与实付研究材料，在观察期（`--days=`，默认 1,825 日）内从新档推进到全图鉴，再分阶段交接实付高级点，并记录各次恢复现金的时点。每条策略输出一行「满级测时」，列出首次科技、各高阶科技首级、普通点倍率满级、代管满级、图鉴全满、六项品质任务与科技全满的到达天数。期内达到的标「实测」。未达到的科技里程碑先用两次真实回访核对稳态解析外推，再按期末稳定原料线的整周期产值与平方根权益求出路线累计报价首次够用的天数，标「外推」，附剩余点数、每次回访与每日高级点及依据；外推不计后续科技增产，为保守上界。未达到的品质任务按期末普通点时速外推；图鉴没有解析模型，标「未达到」。科技总量与级数由定义推导。金币、高级点、普通点与材料守恒，库存不为负，任务发奖守恒，满倍率整小时入账与长批在线离线等价仍为硬性断言。另用初始代管复核两种回访频率的各抽取里程碑和真实涨跌成交。`npm run balance:tech-time` 只运行测时；`npm run balance:check` 先做目录检查，再运行新档与测时。当前操作验收见[验证说明](../verification.md)。历次设计条件见 [LT-v7 历史方案 §5](../reviews/2026-11-16-time-cost-balance.md#5-实施与验收)。

最近一次长线模拟（每日一次回访，改为测时工具之前的期限版）的结论已失效：当时第 179 日买到首个高阶科技，第 537 日点满当时的 24 项、约 468 万高级点。测时工具尚未在现行 42 项、1,762 级、6,723,660 高级点（含农业新增的研发手册、加工提速、周期改良与精制专精，以及订单的商路拓展、客户协商与订单溢价）下运行，暂无测时结论；溢价销售上线后的市场收益（旧测 111.11%）也未重测。待用户授权后运行。


## 7.7 矿业追加与 v11 差异

新增 M01–M10、IM01–IM16、PM01–PM14，共 40 项。v11 目录共 565 项、467 条生产配方、563 项研发。详见[首批经济交付](../reviews/2026-11-17-mining-economy.md)。既有 525 项的 ID、输入数量与研发拓扑保持，动态批量、周期、基价和研发报价均从全目录重新计算。固定 525 个既有 ID 的周期豁免名单未扩充，新品任意配对绝对差仍须严格大于 10,000 毫秒。

本轮原料下界为2805–2913秒，10项相邻差12秒；基础IM下界4500–4833秒，其中IM05为4660秒；交叉IM下界7000–7185秒；PM下界12000–12481秒。全部40项的下界直接成为本轮生成后的实际周期。常规冶炼能耗抽象处理，煤与盐仅在列明用途的配方扣除。

本轮仅实际执行内容生成，生成过程内建的结构、公式与周期差门槛成功；尚未执行内容检查、独立经济检查、测试、模拟、预览或编译。第7.5和7.6列的是待授权验收要求。
