# 性能规约

本规约来自 2026-11-16 的性能评估与两批优化（[性能报告](reviews/2026-11-16-performance-review.md)）。每条都对应一次实际犯过的错误或已修复的热点。新增或修改渲染、主循环、离线结算、存档、资源和构建脚本时，都要遵守。性能优化不能改变玩法、经济数值、BigInt 语义、存档格式与事务、任务统计时机和画面；牧场和工坊的动画区禁止因为优化而回退成图标或静态图。

## 1. 渲染与重绘

1. **禁止按时钟整页重建。** `canvas-ui.js` 的 `redraw()` 只能在结构签名变化时运行。签名包括布局、状态、弹窗、计时 epoch，以及对世界做的深比较；`clockMs`、`wallAnchorMs`、`revision` 不参与比较。曾经的错误：ticker 每秒调用 `paint()`，每次销毁并重建整棵显示树和全部动画；5 秒自动保存也因为签名包含“提交世界身份”而整页重建。
2. **随时间变化的显示只做增量更新。** 倒计时、进度条、动画帧都由 ticker 改现有节点的属性，不能为了它们触发 `redraw()`。新增随时钟变化的数值时，必须接入逐帧更新路径；如果放进静态绘制，签名不变时它会停住不动。
3. **新增可见字段必须进入签名。** 世界里的字段默认参与深比较。如果界面开始依赖世界以外的数据（例如模块级缓存或异步结果），必须把它加进签名，或者在变化时主动调用 `requestRender`/`redraw`。
4. **Text 和 Graphics 只建一次。** 不要在每帧都新建 Text，或者对 Graphics 执行 `clear()` 后重画。提示和飘字只建一次，之后逐帧只改 y 和 alpha。进度条的宽度先量化到设备像素，再和上一帧比较。周期性的矢量动画（例如鱼池水波）预烘焙成 `GraphicsContext` 轮换使用；共享的上下文不能随单个实例一起销毁（`destroy()` 不传 `context: true`）。
5. **按脏标记渲染。** Pixi 的自动逐帧渲染已经移除，改为只在画面变脏时调用 `app.render()`，另外每秒兜底渲染一次。任何改变画面的代码，包括新的输入事件、纹理到达、动画挂载或卸载、文字或颜色变化，都必须标脏（`requestRender` 或现有的脏标记）。每秒一次的兜底只是安全网，不能替代标脏。
6. **重建时复用动画。** 动画挂在独立的 holder 上；重建前先停放，键和全部挂载输入都一致时转挂到新树，否则在同一次 `redraw` 中销毁。新增动画类型时，必须给出完整的键和挂载输入，不能只按序号复用。
7. **重绘必须防异常。** 置位的标志（例如 `building`）一律放在 `try/finally` 里复位。曾经的错误：精制升级对话框里 `compact(null)` 抛错，`building` 一直停在 true，之后所有重绘都提前返回，画布卡死。异常要照常抛出，不能吞掉。

## 2. 主循环与数据复制

1. **热路径禁止 `structuredClone(world)`。** 预演显示用的世界用 `projectWorld()` 做投影复制：只浅拷贝 `advanceWorld` 会修改的字段，其余按引用共享。前提是视图从不修改传给它的世界；视图代码不得写 `ui.w` 或 `display`。如果 `advanceWorld` 开始修改新的字段，必须同步扩充投影复制的范围。
2. **不要为了取一项而算全部。** 例如牧场页只需要当前引导任务，就用 `activeGuideTask(world)`，不要调用 `objectives(world)` 再从结果里 `find`。新增页面数据时同样如此。
3. **成员判断用 Set。** 在循环里对 `unlocked` 之类的大数组调用 `includes` 会变成 O(n²)。每次渲染建一次 `new Set(...)`，传给内部函数使用。
4. **缓存按输入对象作键。** 例如引导状态按提交的世界缓存在 WeakMap 里，不要每次操作都重新计算。

## 3. 离线追赶（`src/game/world.js`）

1. **事件循环不做全槽扫描。** `productionRestarter` 只在第一次完整扫描所有槽位；之后每个事件只重启本次完工的设施，以及本次完工的工位和投入物品刚入库的等待工位。开批顺序、时刻、消耗和入堆顺序都和完整扫描相同。
2. **不变量：** 推进期间配方、等级、reserves、科技、`world.stations` 都不变，库存只会因为入库而增加。**今后如果有任何改动会在 `advanceWorld` 期间修改这些量，必须同时让调度器失效，或者回到完整扫描。**
3. **账本贡献按批结算。** 同一次 advance 内评估倍率不变，所以累计产值后只在 `finally` 里按开方差记一次（`productionContributionBatch`），不要在每次入库时开方。新增入库路径时也必须走 `deposit`，并且由同一个 batch 结算。

## 4. 存档

1. **保持 5 秒保存间隔，不跳过保存。** 每次保存都会推进 `wallAnchorMs`/`clockMs`，拉长间隔会改变离线结算的阈值。
2. **常规保存跳过深度校验。** 存储中的记录正是本会话刚写入的那条（修订号加 8 个标量标记一致）时，跳过 `readRecord`；首次保存、失败之后、标记不符、`replaceCorrupt`，以及每第 12 次保存，都走完整校验。标记只在事务提交后记录。新增写 `current` 的路径时，必须生成新修订号，或者清除标记。

## 5. 纹理与资源

1. **纹理缓存要有上限。** 只对图标（约 200 个）和场景（约 40 张）做 LRU；动画纹理和本次构建中绘制过的纹理永不淘汰。淘汰用 `Assets.unload(url)`，不能只调用 `texture.destroy()`，否则 `Assets.load` 会返回已销毁的纹理。新的纹理加载入口必须声明自己属于哪一类。
2. **大 JSON 不进首包。** 运行时只导入 `src/content/crop-visuals.runtime.json`。这个文件由 `scripts/compile-crop-visuals.mjs` 按白名单从 `crop-visuals.json` 生成，不能手改。运行时开始读取新的字段时，先把字段加进白名单再重新生成，否则读到的是 undefined。导出用的元数据只保留在完整文件里。
3. **离屏剔除和虚拟化保持不变。** 动画、图片的离屏卸载，列表和研究树的虚拟化，页面切换时 `destroy({children:true})`，隐藏标签页时停止动画、保存和倒计时，这些都不能为了“简化”而删掉。

## 6. 构建与发布（`scripts/build-offline.mjs`）

1. **路径统一用正斜杠。** 不要用 `node:path` 的 `join` 拼发布路径。在 Windows 上它会产生反斜杠，导致 `startsWith('dist/…')` 过滤失效，`sw.js` 自己也被列进预缓存。
2. **只预缓存首屏必需的文件。** WebGPU、Canvas 渲染器和无障碍分块只在需要时加载，不预缓存，但保留在 `dist` 中。升级 Vite 或 Pixi 后要核对分块名是否还能匹配。
3. **不发布运行时不加载的资源。** C02 起的作物旧图集按 `loadPlotTextures` 的规则从 `dist` 中删除，源文件不动。修改加载规则时必须同步修改这里的删除规则。

## 7. 提交性能改动的要求

1. 每项改动都附上等价论证：输出、顺序、时序、像素是否一致。做不到逐像素一致时（例如水波按帧起点计算，相差不到一帧），要写明差异的量级，由 PM 裁定。
2. 无法证明等价的情形，保留原来的慢路径，不要猜测。
3. 测试、剖析、预览需要用户授权（见 [AGENTS.md](../AGENTS.md)）。建议的验证有：离线追赶结果逐字段对比；任务和研究报价结果对比；画布逐帧截图对比；用后期存档在 4 倍 CPU 降速下做 Chrome Performance 剖析。
4. 仍待决定的项：遮罩改子帧纹理（S5）先剖析再定；抗锯齿和分辨率（S6）、离线 Worker（S7）按报告保持不变。
