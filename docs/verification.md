# 验证

矿业验收另外覆盖：40新品与全目录（含新品互比）基础周期差严格大于10秒；旧档缺M字段的缺省迁移、现批数量/起止快照保留、矿洞开采/取消/升级/离线/周回；33项经营改良逐项上限与1474级全满旧回执；M/IM/PM研发可达、品质池、行情、图鉴/仓库来源与任务成功事件。矿车静态分镜的合成与独立审图已获本轮明确授权，其他测试/预览按本轮独立授权执行，不因本页列出而自动获得许可。

以下是取得用户明确授权后可执行的验收流程。当前开发期间不运行测试、预览或试编译。编译由主管在模块完成后执行一次。

```sh
npm run check
npm run build
npm run balance:check
codex execpolicy check --rules .codex/rules/project.rules -- git push origin main
```

浏览器验证使用 320、390、480 逻辑像素宽的竖屏，以及横屏。检查页面只挂载一张画布、横屏两侧黑边、旋转后仍停留在当前页面。

发布候选版先用新浏览器档案打开站点首页。等离线缓存安装完成后普通刷新两次，确认首页和存档正常加载。在线打开 `/index.html` 时允许站点重定向到首页。断网后刷新首页应由离线缓存加载；复网后普通刷新应加载线上版本。用已安装旧离线缓存的档案再执行一次，确认旧缓存能自动替换。

经营烟测路径为给空田播种小麦并等待首次收成、安排面粉、预留小麦、研究面包、继续磨粉并安排面包、出货与购地。首次出货应发放 1 点高级研发点。完成主线后打开任务确认长期目标，刷新后核对金币、库存和任务。使用第二个标签验证过期修订不可覆盖新记录。生产构建下可离线重开；计时以已结算锚点计算，初始上限 6 小时。

出售庄园烟测覆盖零点交接、按累计产值结算的高级研发点与经营评估倍率。确认后检查回到田地、金币恢复为 3,000、加工位和精制位各重置1空闲工位，研发与任务进度保留，再刷新核对奖励、工位重置与任务状态。

正式验收使用 [式样书第 11 节](game-design.md#11) 和 [界面与交互规格](ui/qa.md)。未接入的正式玩法以架构文档为准。

用网络面板确认游戏内列表仅在图标进入视口时按需请求 WebP。构建产物的预缓存清单中应无 PNG 原图或 WebP 图标。

科技树验收覆盖单指和鼠标拖动、双指捏合和滚轮缩放、节点索引定位、拖动释放时不触发详情，以及浏览器前进后退。对照完整研发条件核对棉花 → 原棉纱 → 棉布巾盒等依赖。研究的三个页签为「品种配方」「品质」「经营改良」。品质页区分两种研发点，显示发点倒计时及只读名单。抽取按钮按 100 普通点一次报价，结果按品项汇总。经营改良按类型分组。选择棉花播种后，核对独立图标和仓库产出。按 [新增研发路径](expansion/08-crop-uses.md) 核对工坊的图标及配方。

使用同结构既有存档核对读取、导入与再保存。按[存档与开批规则](expansion/01-operations.md#15-任务金额与存档)核对活动批次件数、工位已扣材料与起止时刻；设施升级使用旧批快照，续批按目录基础批量与有效倍率。

以固定账户种子复核两段不同比例的整小时入账、续档余量、单抽与全抽等价及旧档领奖凭据。行情核对产值门槛 99,999→100,000、购买前生成、升级后保留当日行情、同日周回、日期回拨、三轮抽样、0% 无标记、预测与重置，以及库存或行情变化导致整笔报价失效。核对最高正档 +200% 与旧正档 +11% 可读回，+23% 与 +201% 必须拒绝。科技全满在 1,474 级一次到账。
