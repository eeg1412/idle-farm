# 订单中心

订单中心建在大地图主路右侧，位于田地下方、鱼塘上方。点击建筑、门牌或右上菜单的「订单中心」进入，网址为 `#/orders`。每张订单显示商品名称、所需件数、当前库存和收益；列表与弹窗均在同一 PixiJS 画布内操作。

所需件数和库存以件计，按[数字显示规则](../numbers.md)缩写。收益为一行「图标＋数量」，样式同任务卡奖励行（`ui.rewards`），依次为：金币（该单全部金币报酬），报酬倍率涨跌标记跟在金币数量后，外加黑色括号，如「(▲ ×1.2)」，括号内标记仍按行情标记样式显示绿色或红色（括号只用于订单收益，仓库等其他倍率标记不加）；普通研发点（交付发放的点数，挑战订单含开拓奖励，按普通研发点倍率加成后合为一个数）；时空胶囊（挑战订单首次完成奖励，数量大于 0 时显示）。各项数量按数字显示规则缩写，例如 10,500 金币显示为 10.5K。普通视图的订单卡与订单详情的收益行以标题「报酬」开头：图标收益放得下时与标题同一行，标题居左、收益居右；放不下时收益换到标题下一行。紧凑视图的小卡第一行为「需 N 件」，第二行为「报酬:」（半角冒号，与金币图标之间留小间距）后接同样的图标收益；小卡上的订单种类与状态标签使用 11 号字，普通视图订单卡与订单详情的标签不变。

普通视图的订单卡与订单详情在当前库存下方显示该商品的「当前产能」，未接受与已接受订单、三种订单类型都显示；紧凑视图不显示这一行。取值与仓库[每小时产出与支出](warehouse.md#每小时产出与支出)中该商品的净变化相同，数字格式同该图表：正数显示绿色和 `+`，负数显示红色，绝对值不足 1 件／小时显示默认颜色的 `0`。该商品没有生产时，这一行改为显示原因，按以下顺序取第一条成立者：配方未研发显示「未研发」；已研发但没有设施或工位安排该商品显示「未安排生产」；已安排但产出为零（生产工位全部因原料受限）显示「缺料」；部分工位受限时显示数字。原因文字为红色。

普通视图的订单卡与订单详情中，未接受订单在「当前产能」下一行、收益行上一行显示「标准完成时间」：假设玩家现有全部工房位都改做该商品、按各自当前等级与科技满速运转（不计原料，不看工位当前配方、商品是否研发），实时计算交齐全部件数所需时长，格式同倒计时；没有工房位时为红字「未安排生产」。标签右侧有圆形小「？」，点击后订单管理员升起说明这一项（列表卡上点击不打开详情；详情中点击时管理员显示在详情之上，结束后详情不变）。见[标准完成时间](../../tasks/2026-11-26-order-standard-time.md)。已接受订单不显示标准完成时间，改为在「当前产能」下一行显示「预计完成时间」；三种订单类型规则相同，紧凑视图两行都不显示。预计完成时间按以下口径计算：只计该商品此刻正在运行的产线（设施或工位有进行中的批次），停着等料的工位不计入；进行中的批次在其结束时刻到账该批锁定的件数，之后每隔该配方当前周期到账一批，件数按当前等级的每批产量，不检查后续原料；从「库存 − 行脚商预留」开始累加，第一次达到所需件数的时刻为完成时刻。显示规则：
- 库存扣除行脚商预留后已够所需件数：绿色「订单完成」。
- 配方已研发、至少一个设施或工位的配方为该商品，但尚无可计算的运行批次：灰色「计算中」。
- 配方未研发或没有任何设施、工位安排该商品：红色「无法计算」。
- 其余情况：默认颜色的剩余时长，随时钟每秒倒数，格式同订单页倒计时：一小时以上为「3 小时 20 分」，不足一小时为「20 分 5 秒」。

同一商品有多张已接受订单时，每张按当前库存各自计算；一张交付后库存减少，其余订单的预计完成时间随之变长。后续批次缺料和离线超过代管时长不计入计算，出现这两种情况时实际完成晚于显示值。

列表沿用田地的「缩小／放大」切换紧凑与普通视图，按可用宽度排布卡片。两档卡片与订单详情顶部的标题区居左排列：左侧为商品图，右侧上行为商品名称、下行为状态标签，文字块相对商品图垂直居中。下行先显示订单种类标签，再显示状态标签：紫色「高额订单」、青色「普通订单」、橙色「挑战订单」。页头依次为「今日高额订单 已生成 / 上限」「今日替换 已用 / 上限」。商品图边长普通视图为 50，紧凑视图与订单详情为 34。浅蓝色「未接受」表示还可接单，金色「待备货」表示已接受但库存未齐，绿色「可交付」表示可以一次交齐。

点击普通或紧凑视图中的订单卡即打开详情，卡上省去箭头。生产链树直接显示在详情内，原料在上，经过各级加工品连到下方的订单商品；多条路径共用同一材料时只画一个节点，保留所有生产连线。每条配方只画一次、统一棕色：各材料向下汇到产物上方，以一个箭头进入产物；生产链不做选中高亮，卡片不加关系色边框。每张卡片的标签显示本单需要件数「需 N」：从订单件数起逐级按基础批量取整批数（批数 = ⌈需要件数 ÷ 每批产出⌉），乘以每批材料用量得到下级需要件数，多条路径共用的材料累加。卡片按打开详情时的研发状态着色：已研发为绿色、标签「需 N」；未研发为灰色、标签「未研发 · 需 N」。挑战订单的目标商品尚未研发时，详情中「生产链」标题换为「生产链／科技树」切换页签，默认生产链；「科技树」显示目标商品及其全部研发前置，节点状态与研发页相同（已研发／可研发／材料不足／前置未完成），以树形同生产链的高度与拖动规则呈现，点节点打开该配方的研发详情。目标研发完成后不再显示页签。

树的高度在底部固定的「接受／替换」或「交付／排产／放弃」按钮栏测得后确定，铺满上方信息到按钮栏之间的可见空间，不被按钮栏遮挡；可见空间不足 170 逻辑像素时保持 170 并由详情滚动。树不设工具栏和图例说明，没有「查找节点」「－」「＋」按钮。树沿用[科研树](research.md#品种配方)的拖动平移、滚轮与双指缩放。打开详情时以常规缩放定位到订单商品，超出画框的部分可按住拖动平移；整条链在当前缩放下完全可见时，树居中且不平移。点树上节点打开全局物品详情（`src/view/item-chain.js` 的 `showItemDetail`，任何页面可调用）：顶部左图标、右名称与来源，下列当前库存，从订单进入时另列「本单需要」；其下以生产链树呈现，该物品居中高亮，上方为完整上游材料链，下方为直接以它为材料的物品（一层）。树的样式、拖动与高度规则同订单生产链；从订单进入时卡片标签显示本单「需 N」，否则显示来源。「本单需要」与「需 N」只在来源订单仍未结束，且商品、件数和报酬与进入时一致时显示；订单交付、放弃、过期、被替换或件数报酬变化后，已打开的物品详情保留，并按非订单形式显示：不列「本单需要」，卡片标签显示来源。点树中其他节点再打开该物品的详情，关闭后逐层返回。生产链与物品详情的树节点以指针点选。

| 状态 | 玩家操作 |
| --- | --- |
| 未接受 | 接受后锁定。库存扣除行脚商预留后已够所需件数时，「接受」按钮换为绿色「立即交付」，位置与按钮数量不变，订单卡与订单详情相同；点击一次完成接受与交付，结算与先接受再交付相同（含挑战订单的开拓奖励、首次完成胶囊与高额衰减计数）。库存不足时显示「接受」。「替换」按钮始终显示；当天还有替换次数且有可替换品时可替换为另一种商品，否则按钮为灰色，点击浮现红色提示：次数用完为「今天的替换次数用完了」，否则高额与普通订单为「多做几种商品才能替换」，挑战订单为「没有别的新商品可挑战」。 |
| 已接受 | 按钮行依次为绿色「交付」、金色「排产」、「放弃」，订单卡与订单详情相同。三个按钮排在同一行并使用同一字号：宽度不足时整行取各按钮适配字号中的最小值。未接受订单的按钮行各按钮单独适配字号。库存够整单时用「交付」手动交付，也可放弃。加工保留量不减少可交件数。交付按确认时的实际库存结算。 |

点「放弃」先打开居中的「放弃订单」确认弹窗，正文为「确定放弃「商品名」×件数 的订单吗？」，下方一行灰色小字：高额为「订单作废，不发报酬，今日高额订单名额不返还。」，普通为「订单作废，不发报酬。」，挑战为「订单作废，不发报酬，今天不再有挑战订单。」，按钮为「再想想」和危险样式的「确认放弃」。点「确认放弃」才放弃订单；从详情进入时，放弃成功后同时关闭确认弹窗与详情。列表卡与详情的放弃流程相同。接受、替换、交付不经确认。

点「排产」按[排产规则](../../game-design.md#订单中心)为该订单计算方案。无方案时按钮为灰色，点击浮现红色原因，按以下对应关系取文案：

| 情况 | 文案 |
| --- | --- |
| 库存扣除行脚商预留后已够所需件数 | 库存已够交付 |
| 生产链需要的某类设施或工位一个也没有 | 缺少{设施}（如「缺少鱼塘」） |
| 可改动的产线凑不出完整生产链 | 没有可用的{设施}（如「没有可用的工房位」） |
| 生产链上仍需生产的物品未研发 | 缺少「X」的配方 |
| 推荐方案为空，且「产线」拉杆上限为 0 | 产线已排好 |
| 订单已交付、放弃、过期或不存在 | 订单已结束 |
| 其余情况 | 暂时无法排产 |

{设施}依次取田地、养殖场、鱼塘、矿洞、料坊位、工房位。有方案时点「排产」打开「排产」预览弹窗。弹窗打开时计算一次方案并定格，之后内容不随经营状态更新。弹窗依次显示：
- 「预计完成时间」：显示计算时刻的静态文字，不倒数：库存已够为「订单完成」，可计算时为剩余时长，否则为「无法计算」。按方案执行后的状态计算：执行后已有运行中批次、按订单卡口径能算出时沿用该结果；否则按排产后订单商品的真实每小时净产出估算，剩余缺口 ÷ 每小时产出；产出为 0 时为「无法计算」。
- 「产线」行与拉杆：预计完成时间下方一行，左为「产线」，右为订单商品新增产线数；其下为与仓库出售相同样式的进度条拉杆，调整该数量。范围下限为 0（订单商品已有产线时）或 1，上限为订单商品所在类别的可用产线数，减去上游每个没有产线的缺口环节各 1 条；默认值为推荐的平衡值。上限不大于下限时不显示这一行与拉杆。拖到新值时按当前状态与该数量重算一次方案与预计完成时间并定格。该数量排不出方案时正文显示对应原因文案，只留「取消」，拉杆保留，可拖回其他数量。
- 变更列表：按新配方所在设施分页签，「原料」为田地、养殖场、鱼塘、矿洞，「中间产物」为料坊位，「商品」为工房位。只显示有变更的页签，只有一个页签时不显示页签栏。「原料」页签内按农业、畜牧、水产、矿业分组，各组有小标题，没有变更的组不显示。每条变更为一张卡片：上为原配方图标 → 新配方图标，原产线未安排配方时只显示新配方图标；下方小字为新配方名与设施位置（如「田地3」）。卡片常规宽度排两列，可用宽度窄于 280 逻辑像素时排一列。
- 底部按钮「取消」与金色「确认排产」。变更为空时「确认排产」为灰色，点击浮现「无需改动」。

弹窗不提示运行中的批次。执行时运行中的设施批次作废，运行中的工位退回本批已投入材料。

点「取消」关闭弹窗，经营状态不变。点「确认排产」时按当前状态与拉杆所选数量重新计算方案，逐项比较设施、序号、原配方、新配方（不比较批次是否运行中），与弹窗显示的变更一致才执行，成功后关闭弹窗并浮现「已排产」；不一致时不做任何改动，浮现红色「情况有变，请重新排产」，弹窗按当时状态重算一次方案并定格显示。打开或重算时订单已结束，正文为灰色「订单已结束」，只留「取消」按钮；无方案时正文为对应的灰色原因文案。

交付与立即交付成功在同一事务发放普通研发点：普通订单 50、高额订单 100、挑战订单 200；挑战订单另加出单时写入的开拓奖励（`100 + 100 × 出单时研发缺口`），合计后乘普通研发点倍率 `(100+4L)%`（[品质](research.md#品质)）。成功均显示 Toast「已交付 · 订单奖励」，后接本次入账的金币、普通研发点与时空胶囊（挑战订单首次完成时）的「图标＋数量」项，值为 0 的项不显示，数量按[数字显示规则](../numbers.md)缩写；同次交付发放任务奖励时并入同一条 Toast（[提示分配](../feedback.md#提示分配)）；替换成功浮现「已替换」。除排产外，操作失败不浮字。

有任一锁定单可整单交付时，地图订单中心门牌右上角亮圆点，位置与样式同其他建筑的提醒圆点；右上菜单的「订单中心」格子右上角同时亮圆点，与其他菜单格提醒圆点同位置同样式。订单管理员的可领回礼只点亮「经营」与「角色管理」，不点亮订单中心门牌与「订单中心」格子。订单中心页面自身的标题旁不显示圆点。交付、放弃、库存变化、周回及恢复存档后重新判断；另一张可交订单仍在时继续点亮。

配方和品种选择弹窗按锁定订单标记「订单商品」及「订单原料」。原料取整条实际生产链，包括中间产物，按物品 ID 去重。订单结束后，仅保留其他锁定单仍需要的标记。

订单中心使用独立岗位背景。男女管理员各有四表情立绘和一张完整开屏场景画，开屏按本岗当前选择抽取。新档与旧档缺少该岗位时默认选男性。两人沿用岗位资料、形象切换、送礼和回礼。打开 Dialog 后原对白继续，收礼后立即逐字感谢；从管理员列表点资料不触发额外对白。

订单列表在现有订单之后，为今日剩余名额各画一张统一空列表样式的占位卡（`orderPlaceholders`，不可点击），原因、倒计时与进度条都在卡内。第 i 张预计时刻为下次尝试 + i × 30 分钟，依次判定：可接商品不足→「能接的商品种类不够」；订单栏已满→「订单接满了」；晚于本地次日零点→「今天赶不上了」；否则「下一张订单在路上」+ 到该时刻的倒计时。本周目未产出商品时第 1 张显示最早商品批次的倒计时与进度条（无排产时提示去工房位做点商品），其余为「还没开始接单」「第一件商品做好后，再等约 N 分钟」。今日高额名额用完时，按下次检查点画一张普通／挑战订单占位卡（「下一张订单在路上」倒计时、「订单接满了」或「能接的商品种类不够」；晚于次日零点不画），列表之后不加额外提示。

订单管理员按其他岗位的情境帮助机制，在订单中心依当前订单给出帮助：有可整单交付的锁定单时提示交付，有未接受订单时提示接受，暂无订单时说明当前没有订单。可交付与未接受两条情境同时成立时两条都列出；全部订单已接受但均未备齐时不加情境帮助。奥林与茜梨各有一套帮助文案，分别符合各自人设；触发、对白队列、送礼与回礼机制同其他岗位。[经营、计价与跨日规则](../../tasks/2026-11-22-order-center.md)
