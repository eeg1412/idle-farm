# 经济与数值准则

- 适用：新增或修改品项、配方、设施、工位、研发、品质、永久科技、RP、离线、任务、存档迁移的任何人（含子代理）。
- 优先级：`AGENTS.md` ＞ 正式式样（`docs/expansion/01`、`02`、`05`、`07`，`docs/game-design.md`）＞ 本准则。本准则只汇总现行规格的不变量与核对方法，不另立数值；发现与上位条文冲突时以上位条文为准，并在差异说明中列出冲突，不得单方面按本准则改数据或代码。
- 依据：[LT-2026-11-v4 实施说明](reviews/2026-11-16-economy-balance-pass2.md)（下称“实施说明”，B1–B14 为其 §2 问题编号，† 为其手算首版参数）。[ECO-01 方案](reviews/2026-11-16-economy-rebalance-plan.md)（下称“方案”，P1–P12 为其 §1 问题编号）与 `docs/balance.md` 为历史资料，只用于解释“原因”，不作取值依据。
- 现状数字由只读检索 `src/content/game-data.json`（balanceVersion=LT-2026-11-v4）、`src/game/world.js`、`advancement.js`、`objectives.js`、`prestige-ledger.js`、`scripts/long-term-balance.mjs` 与 `docs/expansion/07` 样例表得出；标“手算”的为按上述文件数值的人工计算。未运行游戏、测试、模拟、生成器或构建。

## 1. 金币尺度与数值类型

**E-01 BigInt 与十进制字符串【不变量】**
- 规则：金币、件数、库存、产值、T、prestigeCredit、RP、任务奖励全部用 BigInt；存档与 `game-data.json` 中的经济数量（`price`、`output`、`inputs`、`coins`、`costs`）为匹配 `^(0|[1-9]\d*)$` 的十进制字符串。浮点只允许出现在生成器计算阶段（B(e) 插值、材料时限插值、六次方根估计），写入数据前必须取整（ceilDiv、round 或 3 位有效数字），六次方根须用 BigInt 校正到 `k⁶ ≤ x < (k+1)⁶`。运行代码中的除法一律为整数除法，取整方向在式样中写明。
- 原因：AGENTS.md 规定；后期金额达 10¹⁶–10²⁰（PT49 研发金币 1.49×10¹⁷，runs100 门槛 7×10¹⁹），超出 `Number` 安全整数（约 9×10¹⁵）。
- 检查：遍历 `items`/`research` 的上述字段做正则匹配；在 `src/game` 中检索经济路径上的 `Number(`、`parseFloat`、`Math.` 调用。
- 违反：拒绝合入；改为 BigInt 实现。
- 现状：满足（`sixthRoot` 已做 BigInt 校正）。

**E-02 最低基价保证每级品质都涨价【不变量】**
- 规则：所有品项 `p ≥ 9`。等价于品质售价公式 `P(p,q)=p+⌊12p(q−1)/100⌋+⌊p·max(q−10,0)²/1000⌋` 在 q1→q2 时增量 `⌊12p/100⌋ ≥ 1`。
- 原因：P6，旧小麦 q2 花约 128 金加材料后单价仍是 3→3。
- 检查：`min(items[*].price) ≥ 9`。
- 违反：整体提高金币尺度（按 E-03 联动），不得单独抬某一项价格。
- 现状：满足，最低价 C01=30（其次 C02=74、I01=95），品质 1/2/3/4 为 30/33/37/40。

**E-03 起始金币与尺度联动【不变量】**
- 规则：(a) `startingCoins ≥` 首块可购买农田报价，且 `≥` 引导第一个研发节点（P01）的金币；(b) 若金币尺度乘以 s，同一版本内必须同时换算：全部售价、设施/工位购买与升级系数、研发金币、品质金币、任务奖励、金额类任务阈值（如 `farmIncome`）与累计产值门槛（`taskProductionGates`）、`startingCoins`；存档中的 `coins`、本轮 `productionValue`、`lifetimeProductionValue`（T）一次性 ×s；RP 常数换算到“同一进度得到同样的 RP”。
- 原因：方案 §3.1、§6；只换算一部分会让旧档凭空变富或变穷，或让 RP 随尺度膨胀（P5）。
- 检查：在 `world.js` 读 `startingCoins` 与新档 `facilityOffer(world,'C')` 报价；对照 `docs/expansion/01 §1.5` 迁移表逐项核对换算清单。
- 违反：补齐换算或撤回尺度变更。
- 现状：(a) 满足，`startingCoins=600` ≥ 第 3 块田 600 ≥ P01 金币 120；首座牧场、鱼池同为 600。LT-v4 未改金币尺度（C01 仍为 30），v3→v4 不做换算。

## 2. 原料定价

**E-04 原料收益随代际严格递增【不变量】**
- 规则：同类主线按 ID 顺序（C01–C50、L01–L10、F01–F10，g 递增）相邻 `r(下一项)/r(上一项) ≥ 1.05`，且 C、L、F 单价各自严格递增。分支品种（C51–C68）按自身 g 落在同一曲线上，`r` 与同 g 主线公式值偏差 ≤ 1%；g 相同的两项 `r` 与单价相等。作物产量恒为 2、鱼恒为 1，单价不得因基础产量跳变而倒挂。
- 原因：P2（旧 C17–C27 收益持平）；B11（v3 作物单价 11 处倒挂，因基础产量上跳）。
- 检查：按 §0 由 `g`、`σ` 计算 `u`，并以 `p·out/t` 复核 `r`；逐对比较相邻比与单价。
- 违反：回到生成公式修正，不在数据里手调单项。
- 现状：满足。【v4 参数】`price = ceilDiv(σ·5·g²·(g+127)·t, 1000·20016·out)`；C01–C50 相邻 `r` 最小增幅约 7.9%（C39→C40，g 204→210，手算）；同 g 支线与主线同价（如 C10/C51、C13/C57）；07 §7.5 列 C、L、F 单价各自严格递增为生成核对条件。

**E-05 每秒收益只由代际与行业决定【不变量】**
- 规则：(a) 三行业设施购买与升级费用相同（E-08、E-09），行业差异只由行业溢价 σ 与生产周期体现：同 g 时 `r_L(g)/r_C(g) = σ_L/σ_C`、`r_F(g)/r_C(g) = σ_F/σ_C`，偏差 ≤ 1%（`r_C(g)` 取作物公式在该 g 的值）。(b) 代际秒 g 与生产秒 t 分开：g 决定代际值与研发价，t 只决定一批多久；改 t 不得改变 `r`（单价按 t 等比例放大）。(c) g 只作为生成器内部字段，不写入 `game-data.json`；运行时 `durationMs` 即 t。(d) 溢价只补偿首批等待、换养丢整批与收入成块，不按周期长短再加；不得通过拉长 t 获得更高每秒收益。
- 原因：P1、B10（v3 牧渔设施贵 10 倍却与同 U 作物同价研发）、B12（水产只是畜牧平移）；实施说明 §7：设施升级立即改写当批，长周期没有“升级要等下一批”的损失。
- 检查：对每个 L/F 计算 `(p·out/t)/(σ/1000·u_C(g))`；在 `game-data.json` 检索 `generationSeconds` 应无结果；核对 02 养殖表 L 的“生产秒” = 4×耗时、F 的“生产秒” ≤ 14,400。
- 违反：改 σ 或原料定价公式，两者同版本一起改并重新生成；不得单项调价。
- 现状：满足（由公式保证）。【v4 参数】σ：C 1000、L 1050、F 1150 †；L01 `r`=22.81（t=96），F10 `r`=11,039.79（t=14,400）（07 §7.2）。

## 3. 加工增值

**E-06 加工品必须比直卖投入赚钱【不变量】**
- 规则：每个配方 `p(id) ≥ ⌈1.2·V(id)⌉`（品质 1 口径，增值率 ≥ 20%）。新增配方同样适用。输入品质高于产物品质时机会增值可以为负，这是允许的专业化取舍，任务与 UI 不承诺其为正。
- 原因：P4，旧 P13 增值 +4%、PT08 0%，加工不如直卖原料。
- 检查：对 `items` 中 `inputs` 非空的 437 项计算 `p/V − 1`。
- 违反：改配方定价公式，不改输入种类或数量。
- 现状：满足（由公式保证：m ≥ 1200‰ 且工时项非负）。【v4 参数】`price = ceilDiv(m·V·20016000 + ω·t·N_ref, 1000·20016000)`，m/ω（‰）：I/IL/IF 1200/500，P/PL/PF 1300/750，PD 1350/875，PT 1400/1000；样例增值率 I01 58%、P01 58%、IL01 25%、IF01 22%、PD01 49%（07 §7.3，手算）。

## 4. 设施：产量、升级与购买

**E-07 产量倍率按比例作用于基础产量【不变量】**
- 规则：设施产量写成 `⌊base × M(k) × (100+2Y)/100⌋`（Y 为对应增产科技等级），任何等级或科技项都不得以与 base 无关的绝对件数相加。由此同等级、同科技下两品种的产量比等于 base 比，收益排序与 `r` 排序一致。工位同理按 W(L) 乘算（E-10）。
- 原因：方案 §3.4、P8，旧式 `base + k + ⌊k²/64⌋ + 2·增产级` 让 base=1 的品种每级翻倍、增产满级 +100 件。
- 检查：任取两品种、多个等级，比较 `facilityOutput` 之比与 `out` 之比（允许取整误差 1 件）。
- 违反：退回式样。
- 现状：满足，`world.js` `facilityOutput` 为 `output × M(k) × (10000 + 200·Y) / 10000`。

**E-08 升级费曲线没有墙【不变量】**
- 规则：设 `Δ(k)=total(k+1)−total(k)` 为本级费用，则对所有 k ≥ 5：`Δ(k+1)/Δ(k) ≤ 1.5`；设施等级无上限；报价按“端点累计先折扣取整再求差”。
- 原因：P7，旧 S(k) 在 k>14 后进入 x⁷ 项（30 级 6.84 亿）。
- 检查：用 `facilityUpgradeTotal` 的公式对 k=5…400 逐级算 `Δ` 比值。
- 违反：换平滑曲线族，不加等级上限掩盖。
- 现状：满足。【v4 参数】`total = ceilDiv(A·S'(k)·(10000−折扣基点), 10000)`，A 三行业均为 300；S' 本级增量 25→37→52 的相邻比 1.48、1.41，此后抽查均 ≤ 1.35，k>20 后约 (1+1/k)⁵（手算，与 01 §1.1 一致）。

**E-09 升级优先于新购【不变量】**
- 规则：在每个参考阶段（首小时、首日、第 2 周、第 3 月，或任何经批准的阶段模型状态），“全体设施再升一级”的回本秒 ≤ “新买一座并升到同级”的回本秒；按此最优策略的常驻设施数每类 ≤ 20，上限 40 只在极后期有意义。三行业购买与升级参数相同（E-05）。
- 原因：P7，旧购买 `60×1.2ⁿ` 时第 40 座农田仅约 5 万，后期就是不断开新线；B10，v3 牧渔费用 10 倍。
- 检查：以 `facilityOffer` 的购买与升级公式，按方案 §3.4 的“z、n、等级”参数重算两列回本秒。
- 违反：提高购买几何倍率或降低升级系数，二者择一并重算本表。
- 现状：参数满足设计（农田参数与方案 §3.4 手算时相同，牧渔改为同价后比例不变）；未用 LT-v4 阶段模型重算，见第 14 节。【v4 参数】购买 `600×5ⁿ`（三行业相同，n 为该类额外购买数，免费起始田不计），升级 A=300（三行业相同），上限 40。

## 5. 工坊工位

**E-10 工位升级语义【不变量】**
- 规则：工位字段 `level`（十进制字符串，新建与旧档默认 `'1'`）；每批产出 `out×W(L)`、每种投入 `数量×W(L)`，`W(L)=1+j+⌊j²/64⌋`、j=L−1，输入种类与周期不变；升级从下一批起生效，当前批 `batch.amount`/`batch.inputs` 为开批快照；换配方或清空按 `batch.inputs` 原样退回；缺料时等待整批（需求=配方数量×W(L)），不做部分批次；不新增降级按钮；工位购买与升级不享受任何折扣科技；`sellFarm` 重建为 `level '1'`。`stationOutput`、`stationRequirements`、`forecastHourlyProduction` 与升级报价必须共用同一倍数函数。
- 原因：P4、P9；B5，v3 工位产出随等级线性而成本为 k⁶ 族，工坊增值只占收入 1–2%，配方占研发金币约 99% 却无回报。产出与设施同族后工坊才能跟上设施。
- 检查：式样 `docs/expansion/01 §1.1a` 与 `world.js` `stationMultiplier` 一致；检索上述函数均调用 `stationMultiplier`；`stationUpgradeTotal` 不读折扣。
- 违反：退回式样。
- 现状：满足。【v4 参数】购买 `750/950×25ⁿ`（加工/精制，初始工位不计），上限 48/32；升级 `A·S'(j)`，`A_I=750`、`A_P=950`；W(9)=10、W(10)=11（手算，与 01 §1.1 的 M 表同值）。

**E-11 工位数量不得成为管理负担【不变量】**
- 规则：任一阶段，按“回本更短者优先”的策略，每类（加工/精制）常驻工位数 ≤ 12；超过该数后“再升一级”的回本必须短于“新购并升到同级”。鱼类、畜牧加工工位只需很低等级即可吃完全部来料是预期结果（实施说明 §7），不得为此改配方投入或原料产量。
- 原因：P9，48 个加工位总价约 200 万，产量放大时只能堆工位数。
- 检查：按方案 §3.5 ROI 表方法、以 W(L) 计算各代表配方的平衡数量。
- 违反：调整工位购买倍率（不改上限）；工坊增值占比偏离时按第 14 节调 A_I/A_P。
- 现状：未核实。方案 §3.5 的平衡数量（入门 2、首日 4–5、后期 8–9）按线性产出算出，LT-v4 改为 W(L) 后未重算。

## 6. 新产线解锁与研发

**E-12 研发总价随代际值单调、前置不倒挂【不变量】**
- 规则：(a) 除引导覆盖节点与封顶节点外，把研发节点按 `e` 升序排列，`Total` 不得低于任何 `e` 更小节点的 `Total` 的 99%（e 相差 ≤ 1% 的并列分支允许相等）；07 §7.7 锚点的 e 与 B 必须各自严格递增。(b) 配方节点的 Total 不得高于任何依赖它的（非覆盖）节点的 Total：按 requires 逆拓扑序 `Total(y)=min(Total0(y), 依赖者 Total 的最小值)`；原料节点不封顶。(c) 研发不再按自身 U 定价。
- 原因：P2、P3（旧研发价与产值倒挂）；B6，v3 中 C10（142,000）需先研发 P09（1.71×10⁸），C12 需 P10、P11（各约 2×10⁹）。按上游代际定价后，配方总是出现在它所用原料的同一时期。
- 检查：用 §0 定义计算 `e` 与 `Total` 后排序扫描；对每条 requires 边核对 (b)；生成器 `validatePolicy` 拒绝非严格递增锚点。
- 违反：改 07 §7.7、φ 或生成规则后重新生成，不逐项手调。
- 现状：(a) 由公式保证，未逐项扫描全 522 项；(b) 本次封顶 5 节点（P08、P11、I61、I74、I103）。【v4 参数】`Total0 = 2·B(e)`，锚点 e:B 为 5:100、9:650、200:5.5×10⁵、2,000:2×10¹³、9,600:7×10¹⁵、22,080:7.5×10¹⁶（后三行 †；22,080 = 2.0×F10 的 u）；φ 见 §0 †；523 项研发金币合计 3,663,041,087,990,666,776（07 §7.4）。

**E-13 新产线的解锁门槛不得低于更低档品种【不变量】**
