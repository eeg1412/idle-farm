## 无人值守实装

- 主代理担任项目经理，使用 [farm-task-dispatch](../.agents/skills/farm-task-dispatch/SKILL.md) 组织项目任务指派、拆分与交接，具体实现交给文件所有者子代理。项目经理维护需求及持久反馈清单，负责拆分、输入摘要、所有权、接口冻结、依赖调度、汇总、整合实际执行路径、最终编译及用户同步。按独立成果物拆小任务；只有一个不可再分的输出时，仍使用一张任务卡和单一所有者，不为凑代理数量强拆。
- 每次指派采用 [任务卡](../.agents/skills/farm-task-dispatch/references/task-card.md)：提供背景与目标、精确输入及证据、最少读取文件和章节、与本任务有关的 AI 开发规约摘录及出处、可编辑文件和禁改范围、方法与接口依赖、成果物路径和格式、完成条件、允许验证及未验证项、汇报格式。项目经理先整理必要摘要，避免每个子代理重新探索全项目。
- 文件所有权互斥，共享文件修改和共享资产生成各由一个所有者完成。先冻结跨任务接口，再分配可并行任务；后继任务等待前置成果物和接口交接，不并发改写依赖输出。需要改接口、扩大读取或写入范围时，子代理先报告项目经理，由项目经理更新任务卡和相关任务。
- 子代理只读任务必需资料并完成指定小任务，不自行扩展范围，不覆盖或撤销其他人的改动。按接手、阶段完成、阻塞、交付持续汇报，说明输入、实际文件、接口、剩余项和验证状态；项目经理汇总后向用户定期同步。无人值守期间在已有授权内继续完成可独立推进的工作。
- 项目经理以实际调用路径和源证据核对交付，记录需求对应的接入点、完成情况及剩余限制；不能仅凭子代理报告、素材存在或测试数量宣布行为正确。用户再次报告失败时，重新打开持久反馈项，旧完成记录或通过的检查不能代替本次问题确认。
- 用户明确授权前禁止运行测试、冒烟、预览、试编译、语法或运行时检查，以及任何同类验证；创建 skill 也不授权运行其验证脚本。正常的文件阅读、实现、资源生成与转换属于交付工作。仅所有模块、资料与资源接齐后，由项目经理执行最终编译。
- 如需授权后的验收，使用 [验收步骤](verification.md) 与扩展式样书中的验收用例。

## GitHub 推送授权

- 只有用户针对当前推送明确下达指示时，才能执行 `git push` 或通过其他工具、脚本向 GitHub 和其他远端推送。接管项目、实现功能、修复问题、最终编译和本地提交均不包含推送授权。
- 过去任务中的推送许可不延续到后续任务。每次需要推送时，必须先有对应的用户明确指示；禁止在完成本地工作后自行推送。
- 此约束适用于 `git -c ... push` 等命令变体和自动化流程。`.codex/rules/project.rules` 的命令提示只提供额外拦截，不替代用户授权，也不能通过改写命令绕过规约。

## 开发测试模式

这是用户明确要求的开发专用额外行为，不改变正式版玩法与正常研发规则。

- 仅 `npm run dev` 对应的 Vite `serve`、`mode: development` 启用。在 `/#/settings` 设置页连续点击页头标题「设置」11 下，第 11 下通过现有动作与存档事务发放。离开设置页或点击其他控件时清除未完成的点击计数。
- 发放内容为全部品种与配方解锁、24 项永久科技达到 5 级，以及追加 1T 金币，即 `1_000_000_000_000n`。金币按 BigInt 运算并按现有规则序列化；品质等级没有上限，不属于「全部科技满级」的范围。
- 发放不得冒充正常经营事件，不增加生产、出售、售货收入或其他累计经营统计。成功反馈应在保存事务提交后出现；失败不得留下部分发放结果。
- 开发环境使用独立 IndexedDB 数据库 `idle-farm-development`，正式环境继续使用兼容旧档的 `tianjian-workshop`。开发测试获得的金币与科技不得写入正式存档。
- 开关必须由 Vite 命令类型与模式在编译时决定，不能仅依赖运行时页面、URL 参数、浏览器存储或 `NODE_ENV`。所有 `vite build`，包括 `vite build --mode development`，都必须移除标题触发器和发放模块；构建产物及 `npm run preview` 中不能启用该功能。
- 本功能的开发不构成运行测试或预览的授权。仍遵守本页的验证限制，全部模块完成后由主管执行最终编译。

## 素材

- 小图标按稳定 ID 排入大图的 5×5 透明网格，一格一件，留出足够透明带。确认分隔完整后裁切为单张。原图、规则裁切表和最终图标可按 ID 对照。
- 导航、设施、操作、任务和经营改良各用独立图标。物品图只在表示对应的作物、原料、中间产物或商品时使用。各页横幅独立绘制，界面参考图只用于确定构图、比例和色彩。
- 大图如各页场景逐张整幅绘制。保留全幅 PNG 原图，再按页面比例裁出使用区域并转成 WebP 质量 70。
- 每项新增作物交付一枚物品图标和一幅显示该作物长在地块中的定植场景。新增牲畜与鱼类同样各交付物品图标和设施场景；牲畜另交付独立透明选择图及完整动画资源。场景原图可按格随批维护，发布图为 `public/art/scene-<物品ID>.webp`，规格为 320×320、质量 70。逐格核对对象与 ID、边缘裁切和独立性。最终构建包含 `npm run art:check`，单独执行检查仍遵守用户验证授权。
- 实际界面的 WebP 按需请求，浏览过的游戏图片可由离线缓存复用。源图不进入构建或预缓存。详细规则见 [图标资源与按需加载](assets.md)。

### 作物成长动画

新增或改画作物使用 [farm-crops](../.agents/skills/farm-crops/SKILL.md) 及其按 ID 交付清单。当前覆盖目录全部 68 种作物，后续按目录扩展，不固定数量或遗漏图标、回退场景。

1. 以作物目录 ID 交付种子、幼苗、成长期、成熟期四种前景。植物原画用透明 5×5 网格绘制，独立单株保留足够格间空隙。逐格核对品种、花果、根脚和透明边，再裁切。成长期和成熟期必须有该品种的整株特征，成熟期的收获物画在植株上。
2. 四期沿用同一组 `assets/plot/furrows.json` 根位。每条可种田垄按固定株距铺到两端，只给边缘和中央洒水器留必要空间。按 130×138 卡片尺寸检查成熟期的识别度、遮挡和切帧稳定性。各层依次为天空、田地、作物、洒水器底座、旋转喷头、水滴与落地飞溅。
3. 用 `python3 scripts/export-crop-animation.py` 按 ID 合成图集。保留原始透明图、提示词、裁切记录、单株 PNG、合成 PNG。发布图为 640×640 WebP，质量 70，四格各 320×320，左上种子、右上幼苗、左下成长、右下成熟。新增作物时补登记合成尺寸与早期株型，使资源检查覆盖目录中的全部作物。`C01` 沿用 `assets/plot/wheat/wheat-0.png` 至 `wheat-3.png` 的已确认整幅透明前景，其他作物使用 `assets/plot/crops/<ID>/` 四期单株；不得为统一目录虚构或覆盖小麦原画。
4. 显示周期取实际生长时长与 5 秒的较大值，再均分四期。短于 5 秒的真实收获与展示循环独立，收获与回合结算继续按生产数据运行。成熟末尾只淡出作物，固定 300 毫秒，留空 30 毫秒后切到种子。换种立即切到新作物，配合「减弱动效」直接切帧。
5. PixiJS 只为视口内的活跃种植卡创建动画，并用最近邻纹理。首次可见时按品种请求单张图集，天空、田地和洒水器贴图共用。滚出视口、打开弹窗、换页、后台时停止并卸载动画实例。资源失败使用原有独立设施图，动画 WebP 排除在预缓存之外。
6. 正式构建的 `npm run art:check` 要覆盖目录中每一个作物 ID。发布前核对所有图集的尺寸、透明度、四帧完整性和 ID 对应，检查典型作物的种植位置及切换；在线检查按用户授权和 [验收步骤](verification.md) 执行。

### 畜牧动画

这是用户指定的展示行为，范围已从蛋鸡和黑猪样例扩展为目录全部 10 种牲畜。新增或改画使用 [farm-livestock](../.agents/skills/farm-livestock/SKILL.md) 及其交付清单，新增 ID 同步交付全部资源。经营数据、收成、任务统计和存档结构保持原有规则。

1. 固定背景是同一幅空牲畜棚舍。附属产品类保持成体，交付 4 张 idle 原画；肉类幼年、成长、成熟各 4 张独立 idle 原画。每帧 300 毫秒循环；不使用缩放一张静态动物代替不同阶段或 idle 帧。分类由 `assets/livestock/layout.json` 显式 `slaughter` 登记，并生成 `src/content/livestock-visuals.json`，不可按 ID 序号猜测。
2. 用户明确确认畜牧动画最低展示周期为 **9 秒**，与田地的 5 秒保底分别维护。展示周期取实际生产周期与 9 秒的较大值。肉类三阶段平均分配周期，附属产品类始终保持成体。短于保底的真实批次继续按经济数据收获，展示相位跨真实批次连续。
3. 距展示收获还剩 **3 秒** 时，附属产品类在动物附近接地并淡入对应蛋、奶等产品，动物保持 idle；肉类在同一时点淡出成熟动物，并在成熟阶段实际落脚点淡入对应肉品，以无血腥画面表示屠宰。展示收获后产品及其独立阴影淡出，肉品跨阶段边界保持成熟落点，不跳回幼年位置。淡入淡出均为 300 毫秒 smoothstep，不套用作物的 30 毫秒空隙。新养殖或换养不能带入上一只动物的产品，不增加屠宰操作或额外收成。
4. 动物原图必须由绘图技能调用内置 `image_gen` 生成。保留透明 5×5 原画、固定棚舍全幅原图、提示词、各来源规范网格、逐帧 PNG、PNG 图集和裁切／脚位登记。多来源由 `layout.json` 维护，`npm run art:livestock` 使用 sharp 做裁切、对齐和格式导出，不生成替代原画。动物帧、选择图、回退动物层与复用物品图都不烘焙程序椭圆影子。同阶段四帧共用尺度和固定解剖脚点；源图注册点与 `fixedGround: [138,270]` 不变，禁止逐帧 bbox 重居中、按包围框缩放或加权脚底像素中心漂移，成熟动物保持物种特征。无需为动画另画产品，旧原稿产品格及独立成品只保留历史溯源。
5. 发布动物素材位于 `public/art/livestock/`：`barn.webp` 为 320×320，`animals/<ID>.webp` 为附属产品类 1280×320、肉类 1280×960。图集每行一个阶段、每行四帧、单格 320×320。WebP 质量 70，保留透明通道；原图不进入构建。不再要求或消费独立 128px 动画产品。
6. 每种牲畜另交付 `public/ui-icons/livestock-<ID>.webp`（96×96 透明活牲畜）用于养殖选择，不能用棚舍缩略图、蛋、奶或肉替代。仓库、收成与动画产物共用 `public/wiki/icons/<ID>.webp`（96×96 实际产出），加载 URL 同为 `./wiki/icons/<ID>.webp?game=1`，不另裁另一版产品；默认保留已有图，仅按任务卡明确的单项例外更新持久来源。当前 L02 牛奶改奶桶为已授权例外，其余产物不重画。同 ID 的 `public/art/scene-<ID>.webp`（320×320）作为设施回退，动物重绘时十张回退同步使用新动物。
7. 只在畜牧主界面实际可见的活跃图块挂载动画。沿用单画布命中，滚出视口、弹窗、换页、后台时销毁实例。按需加载、同种共享贴图、加载失败回退独立静态设施图。减弱动效固定 idle 第 0 帧并直接切换阶段与产品显隐。资源检查按目录全部 `kind: L` 项覆盖视觉登记、原画帧独立性、图集尺寸、透明通道、固定注册点／共享尺度、真实脚印几何、脚线下疑似烘焙投影、canonical 物品身份／96px 规格／内容 bounds、活牲畜图、回退及共享棚舍；不要求旧独立产品，不能用元数据或帧数量宣布视觉效果通过。
8. `src/content/livestock-visuals.json` 每 ID 为 `{stages,slaughter,grounding,product}`。`grounding` 长度等于 `stages`，依阶段顺序记录 `{x,y,radiusX,radiusY}`，半径均为有限正数；位置和大小取阶段首帧的真实支撑脚区域，同阶段固定，不必等于注册点 `(138,270)`，不逐帧测量或挪动动物。PixiJS 在棚舍与动物之间的独立地面层，以真实 `(x,y)` 绘制动物影，不加旧 `y+3` 偏移，只在阶段切换时更新几何；全部产物另有独立椭圆影，半径按可见宽度，几何恒定，两者分别乘 `animalAlpha`／`productAlpha`。
   `layout.species[ID].stages[i]` 顶层须显式登记正整数 `supportBandHeight` 与 `supportMaterial`（`golden-feet`／`opaque-feet`），由导出器消费首帧固定脚区及脚部材质选择，不能按固定牲畜 ID 名单推断或补默认值；缺失或非法时报告交付登记错误。`footprint.supportMaterial` 保留材质枚举，`supportSelection` 记录选择说明。旧 `productCell` 为可选历史字段，仅存在时生成 `historicalProductCell`／`consumed: false`，不是新动物必交项。
9. `assets/livestock/atlas.json` 每帧保留 `fixedGround: [138,270]`，增加同阶段共享的正数 `stageScale`、人工解剖脚点 `sourceAnchor: [x,y]` 与实际 `anchorMethod` 说明。`sourceAnchor` 使用原始整张源图的绝对像素坐标；`sourceCanvas.left/top` 是相对此 anchor 的偏移，画布尺寸同阶段固定。导出从 `sourceAnchor + sourceCanvas.left/top` 提取画布，同阶段共用 `stageScale` 与 `scenePlacement`。素材与运行时任务卡交接来源、阶段尺度／解剖脚点、阴影几何及未验收项，不凭四帧齐全保证连贯。PM 审阅真实源图和分镜；浏览器与实际动画验收仍按用户授权执行。
10. `product: {icon: ID, bounds: {x,y,width,height}}` 使用原 96px canonical 图标的可见 Alpha 内容区域，按可见主体底边接地，不将透明边距当脚点。肉品取成熟 `grounding.x/y` 并跨收获淡出保持；附属产物仍在动物附近接地。本轮实现配置为产品可见最长边约 72px、动物影填充 Alpha 0.45、产品影填充 Alpha 0.36；这些是实现选择，不是用户已确认的固定数值，实际画布仍待按授权验收。

用户反馈“牲畜选择图不可辨识”已重新打开。透明选择图进入实际选择网格、详细及仅图标模式的表现仍需按授权进行验收；素材存在、旧完成记录或资源检查通过均不能替代这一确认。

## 界面实装

- 每个主页面及二级页面对应 [v1.14 界面参考](ui-references/v1.14/README.md) 的指定参考图。按对应图的页头、横幅、筛选、正文、主要按钮和底栏顺序实装。通用组件负责颜色、边框、点击区域和响应式排版。
- 田地、畜牧和鱼池用各自的设施画面及操作布局。工坊独立展示配方、库存、批次和材料。研究以科技树展示研发、品质与经营改良，交互和节点结构以 [研究界面](ui/pages/research.md) 为准。仓库、图鉴、任务、设置及出售牧场按各页参考图的分区和阅读顺序组织。
