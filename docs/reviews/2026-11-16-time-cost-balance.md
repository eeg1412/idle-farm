# 按基础工时定价与单品培养

> LT-2026-11-v7 历史方案。v8 调整了金币倍率、最低基价和品质涨幅，后续决定取消单品产量培养。下文保留当时的计算、强制新档决定和验收要求。现行行为见[经营式样](../expansion/01-operations.md)和[数值与平衡式样](../expansion/07-balance-validation.md)。

基线为已发布的 LT-2026-11-v6。目标版为 LT-2026-11-v7，存档从本版新开。原料和工坊使用同一套基价、批量和培养规则。规格通过独立审查后实施，运行和平衡门禁全部通过后更新 Sites。

## 1. 目录、时间与售价

| 量 | 定义 |
| --- | --- |
| `Uⱼ` | 全目录每条生产配方消耗物品 j 的件数之和。每条配方计一次，研发、品质、已解锁情况和设施数量均不参与 |
| `Qⱼ` | 基础批量 `1 + isqrt(floor(Uⱼ/2))`。未被消耗时为 1，`2k²` 用量起为至少 `k+1` 件。同一档批量相同，无类型区分或单项覆盖 |
| `sⱼ` | 固定的基础周期输入。首版把 v6 无科技 `durationMs/1000` 冻结为整秒，原料实用，工坊作下界 |
| `tⱼ` | 实际出表的无科技基础周期。原料等于 `sⱼ`，配方按下文确定 |
| `Aⱼ`、`Hⱼ` | 分摊上游工时 `Aⱼ=Σᵢ qᵢⱼ·Hᵢ/Qᵢ`，含料批工时 `Hⱼ=tⱼ+Aⱼ`。原料的 A 为 0 |
| `R(H)` | 统一目标率 `1+H/3`，单位金/秒。H 以秒输入 |
| `Vⱼ`、`pⱼ`、`rⱼ` | 批理论总价 `Vⱼ=10·tⱼ·(1/10+Hⱼ/30)`，品质 1 单价 `pⱼ=floor(Vⱼ/Qⱼ)`，实际基础产值率 `rⱼ=pⱼ·Qⱼ/tⱼ`。单价小于 1 报错 |

任何品项的 s 须在 1–43,200 秒内。配方按生产 DAG 正序，选满足下列条件的最小整秒 t。任意必需条件在 43,200 秒仍不满足时，指明品项和条件并拒绝生成。

1. `t ≥ sⱼ`，且对各直接输入 i，`10t ≥ 11tᵢ`、`10tQᵢ ≥ 11qᵢⱼtᵢ`。
2. `R(t+Aⱼ)−Qⱼ/t ≥ (11/10)·ΣᵢR(Hᵢ)`。以第 1 条下界和 43,200 为端点做整数二分。左侧随 t 严格递增。向下取整损失小于 `Qⱼ/t`，所以下游实际率 `rⱼ > (11/10)·Σᵢrᵢ`。比较共同整周期内每种直接投入各一座满速专用上游的全部产值，包含未消耗的余量。

第 2 条通过增加基础周期容纳旧同窗要求，完工售价依然由统一公式计算。用同一批量和价格公式直接保留 v6 周期，80 个配方的实际同窗比低于 1.1。例如焦糖饼干 P02 为 20 秒，毛产值 9.8 金/秒，面粉与糖合计约 21.43 金/秒，比值约 0.457。按规则求得最短周期 64 秒，毛产值 24.47 金/秒。

计算周期、H、价率、研发、汇总时用约分的 BigInt 有理数或等价整数交叉相乘。除表内指定整数除法外保留精度，避免浮点先舍入。相同 H 允许实际率因整件取整略有区别。按 H 升序分组，相邻组验证新组最小 `r` 大于旧组最大 `r`，基础品质的每个配方另验 `pⱼ·Qⱼ ≥ 1.2·Σᵢqᵢⱼ·pᵢ`。校验失败应报告上下文，先审改公共公式或经批准的基础周期，再重生目录。

面包仅摊 `2/12 × 26` 秒的面粉工时。鲫鱼实际率是小麦的 3 倍，鸡蛋为 11 金/秒。全目录 525 物品、437 配方，批量 1–12，102 个工坊周期延长，产量与价率排序均符合规则。P169 的 15,246 秒为最长单批，专用供料的首件上界为 24,934 秒，最高单价 144,843,776。最低单价 11，最低同窗比约 1.100084（I56），最低成品批总价/耗材比约 1.977527（P150）。以上为独立静态复算，运行结果在实现后验收。

供料仍使用原 10% 预留。专线开工前预留每种材料的 `qᵢⱼ+Qᵢ` 件可消费库存，同刻先完工入库后扣料。这是稳态排产的起步条件，库存的实物保留设置及其排产、售卖语义照旧。共享线按实际整数件数与科技后周期合计，供给至少为需求的 1.1 倍；工位等级同时提高投入，单品产量升级只提高产出。以上同窗、收益顺序与投入增值指标均以品质 1、设施与工位 1 级、单品升级 0、无科技为准。实盘比较时按各自当前品质和产量估值，例如单独提高面粉品质只抬高出售面粉的机会成本，面包的售价由面包品质决定。

### 可重复生成

在 05 物品机读表把旧代际时间替换为唯一 `基础周期下界秒` 列，第一次由发布 v6 原始目录离线冻结，之后逐品项在该表维护。目录源码只保留 ID、名称、基础周期和生产配方等人工字段。移除旧售价、旧批量重复输入、g/行业系数/旧代际锚点和各项旧硬编码价格。02 表为展示值时引用生成输出，研发表 06 只把前置与耗材 ID 作为权威输入。冻结后的 05 自成生成输入，日后无需 v6 工作树或前一次运行产物。新增品项填周期、原始配方、研发前置和耗材种类，再运行生成器；新增配方先全表累计 U，再重算全部 Q、所有工时、售价和研发。生成前校验未知 ID、非正数、环和既有生产/研发结构，失败不覆盖产物。运行 JSON 保留既有 `durationMs`、`output`、`price`、`inputs`、`research` 接口；出表诊断宜列 U、冻结 s、实际 t、H 和各门槛，顺序稳定且可重算。

## 2. 品种与配方研发

逐项保留 523 个节点的解锁前置、耗材 ID、生产配方输入件数、初始解锁和既有研发材料降费科技。新报价一律从工时和单价重算，包含 P01。以研发前置拓扑计算下列规则。S 是当前节点列出的耗材集合，`M₀=Σᵢ∈S pᵢ`。

1. 基准总价 `B=ceil((30+Hⱼ/2)·R(Hⱼ))`。报价目标 `T=max(B,ceil(5M₀/2),M₀+10,所有有研发报价的工坊前置节点的 T)`。前置为空时该项为 0。
2. 每种材料保底一件。剩余材料预算 `max(0,floor(T/3)−M₀)` 对 S 中材料等分，逐种按 p 向下换算额外件数。每种上限 `max(1,floor(D·Qᵢ/tᵢ))`，其中 `D=max(300,min(3600,ceil(Hⱼ)))` 秒。S 为空时直接跳过材料分配。材料保底高于 D 时明确记录；一次取得一批的物理等待不受报价上限影响。
3. 实际材料现值 `M=Σᵢ pᵢ·件数ᵢ`，金币为 `T−M`。材料占比最高 40%，工坊前置实际总价不高于依赖项。实物降费仍在运行报价时作用于生成数量。检查报错与扣款回滚。

全量独立复算金币 953,236,830、材料现值 313,295,660，最高完整报价 P169 为 135,658,430。C02 需 189 金、小麦 1、面粉 2，P01 需 432 金、小麦 3、面粉 8，F01 需 525 金、小麦 8，IF01 需 3,225 金、鲫鱼 4。两块起始空田种小麦，加免费加工位磨面粉，取得首批面粉后即可再攒少量小麦解锁 P01，无需出货或培养。用有限金币按实际事件重放首面包、首畜牧、首鱼和首复合商品，记录等待与资源来源。

## 3. 品质、单品产量与高级研发点

两类培养在「研究」分别显示，只有已解锁品项可买，默认品质 1、单品产量 0。品质 q 的单价 `p+(q−1)·[1+floor((p+5)/10)]`，1 级原价，依次增加同一整数。产量培养等级 y 的批量 `Q+y·[1+floor((Q+5)/10)]`，每级加数对基础产量先作四舍五入，100→111→122。品质只影响本品售价，单品产量只影响新批产出，工坊扣料仍为配方用量乘工位系数。设施产量为 `floor(培养后批量×原设施等级倍率×(100+2×原增产科技等级)/100)`，工坊为 `培养后批量×原工位等级倍率`。先乘后只取整一次。以 1 级面粉为例，每级 +2 件，I01 批次从 12 件到 14 件，仍消耗 2 小麦；售价 11 时每批毛产值从 132 到 154 金，单位时间消耗不变。

以 n 为已购买级数（品质 n=q−1，产量 n=y）。累计金币 `ceil(a·r·n(n+1)(2n+1)/6)`，品质 `a=200`，产量 `a=300`。累计高级点 `n(n+1)/2`。多级报价为累计端点差，首级均 1 高级点，随后 2、3、4……；品质和产量均无需素材，无降费折扣。支持原级数操作和「最高可升」，金币、高级点及等级一次提交，报价失效或资金不足不改状态。小麦品质首级 1,000 金 +1 点，30→34 金；产量首级 1,500 金 +1 点，2→3 件。

取消普通研发点及专属图标、定时报酬和科技来源。当前 v6 的 `researchPoints` 是高级点，同名读写和图标继续作为唯一货币。完整清点状态、启动/离线、资源注册、文案和历史兼容工具，禁止把高级点当普通点清掉。现有 `firstSale` 仓库首出货任务一次追加 1 高级点与原金币奖励，同一成功事务写领取记录，首点无需周回或购买科技。新档双麦基准首批共 120 金产值，两小时连续产出 72,000 金产值；活动权益仍按真实完工、评估倍率和原平方根累计，出售牧场才领取，`creditPerPoint` 调至 1,000,000，双麦两小时对应 18 点。空档反复交接不会产生点数；点数余量仍跨轮保留。代管仍按原公式为 24/48/72 小时（0/10/50 级）。

删除三项品质材料手册 `qualityDiscount`、`livestockQuality`、`fishQuality`。经营改良分「通用」「农业」「畜牧」「水产」，每种类型从新一行起，窄屏允许组内换行。21 项仍按各自前置和原费用、上限、数值生效，合计 1,050 级、2,007,600 点，科技全满任务保留 ID `techLevel1200` 而阈值从现有科技定义动态推导。累计科技等级只加有效经营改良；单品品质与产量不进科技总等级。长期品质六项全部保留，仅删除 `firstQuality` 主线含文案、奖励表和导航映射。新档任务 16 项主线、14 项支线、36 项长期，共 66 项。

## 4. 存档、事务与生效时点

- 首次升级到 v7 使用固定新 IndexedDB 名称 `idle-farm-v7` 与 `idle-farm-v7-development`，分别代表正式和开发。旧 `tianjian-workshop`、`idle-farm-development` 仅保留原位，启动、回滚、清档和备份路径均只操作当前环境的新库。新世界初始化与新档提示只发生一次，后续经济改版继续使用当前数据库。
- 世界结构升为 schemaVersion 3（新增产量培养与设施批快照），强制 `saveEpoch='v7'`；公开传输封套为 formatVersion 2 并包含同一 epoch。因点数阈变化，`prestigeLedgerVersion` 升为 `LT-2026-11-v7`，新档直接建新账本。当前版路径不跑旧账本迁移。IndexedDB 主档、备份、文件、粘贴和拖入导入均执行 epoch、环境（封套）及现有结构校验。界面提示旧版本存档仅能在旧版本使用。旧封套、缺失 epoch、开发与正式交叉导入一律拒绝，现存主档和备份保持；失败也保留原存档。新版导入仍先预览再确认，并在提交前重验。导入仅替换档案，不发任务金币或点数，不追算导出后的产出。以后售价版本变化但 schema 和 epoch 兼容时仍可导入；显示游戏版本与经济版本不作重开条件。
- 新字段 `world.itemYield` 为已买等级映射，缺失项为 0，保存为十进制字符串，校验 ID 已解锁、等级非负。它与已解锁、品质、经营改良、高级点及任务凭据同样跨周回保留。清档只清当前环境，仍经现有确认和原子替换。旧表残留的普通研发点及旧科技不可成为新档默认状态或有效数据。
- 下一批按当时数据生成。生产继续保存每批 `id/amount/start/end` 与工位 `inputs`；目录更新、科技、单品产量升级和读档不得改变已开批数量、周期或扣料，工位取消退还已记录实物。设施等级主动升级保留立即增产，当前批用 `floor(yieldBase×M(新等级)×facilityYieldBasis/10000)` 计算产出件数，周期不动。开批时保存 `batch.yieldBase`（培养后批量，正整数字符串）与 `batch.facilityYieldBasis`（`10000+200×设施增产科技等级`，10000–20000 间距 200 的整数基点）。读档校验两字段及 amount，与当前目录值无关。开批后购买科技、单品培养或重载目录均保留该批快照。验开批后购买科技／单品产量，再升设施，保存重载与连续升级都只改变设施等级倍率。开批也保留作物植株起始记录。
- 完工产值、T 和活动权益用完工当时单价和快照件数。仓库实卖用出售当时单价，过时报价拒绝确认；历史金币、T、任务领取、统计和账本原值不改。未来同 epoch 新定价的测试用可控的 A/B 目录重开同一存档证明上述时点。在线与离线走同一核心，失败沿用原保存回滚。
