# 2026-11-24 批量升级判定、灰按钮原因、订单空状态、设施空列表

PM：主代理。允许验证：无（用户未授权测试、预览、试编译）。推送授权：无。全部交齐后 PM 执行最终编译。

## 用户原要求

1. 批量升级判定：例如 50 级 ×3 与 1 级 ×1 全选，余额不够全部升级但够 1 级那条，升级按钮仍为灰色。非平均分配模式下，高等级升不起、低等级升得起时，批量 +1 应让能升级的升 1 级。
2. 所有会变灰的按钮，点击后在点击区域上方用红字提示无法点击的原因。沿用已实现的点击处浮动文字，改文字颜色。
3. 订单列表为空时显示当前没有订单的原因：数值未到显示进度条，时间未到显示倒计时，设计界面。
4. 畜牧、鱼塘、矿业列表为空时，使用与其他页面统一的空列表样式。

## PM 解释（非用户原话）

- 1：只改非平均分配。所选各项每项加同一档位（+1／+5／+10），某项整档付不起则本次跳过，不做部分档位。按单项费用从低到高（同价按选择顺序）累加，累计不超过余额的项全部纳入；至少一项可升级即可点击，「确认升级」按实际纳入项扣费。平均分配模式规则不变。
- 2：只对「因状态不可用」的灰按钮提供原因；保存处理中（`waiting`）导致的临时灰态不提示。原因文案为短句（约 2–8 字），不写机制解释。成功浮字颜色不变。
- 3：空列表时按优先级给出一个原因：今日订单已达上限 → 倒计时到本地次日；本周目尚未产出商品（`nextAttemptMs === null`）→ 最近完工的商品批次进度条，无排产商品时只给一句提示；无可用候选 → 一句提示；否则 → 距下次尝试（`nextAttemptMs − clockMs`，有效经营时间）的倒计时。
- 4：L／F／M 空列表改用 `ui.empty(message, { icon })`；C 田地同函数一并替换以统一（田地有免费地块，实际很少为空）。

## 冻结接口

- `buttonAt` 选项 `reason: string`：按钮因 `options.disabled` 或无 `fn` 呈灰色且给出 `reason` 时，点击按钮区域调用 `float(reason, { tone: 'danger' })`，不执行 `fn`；`waiting` 导致的灰态不响应。`ui.buttons([...])` 的条目与 `ui.button(label, fn, options)` 通过展开传入，无需另改调用约定。
- `ui.float(message, { tone } = {})`：`tone: 'danger'` 用红字（描边沿用奶油色），默认保持现有颜色。
- `orders.js` 新导出纯函数 `orderIdleStatus(world)`（见 ORDER 卡），不依赖真实时钟、PixiJS 或 DOM。
