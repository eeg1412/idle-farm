# 订单中心需求与验收

本文记录订单中心的经营、界面、素材、迁移及验收要求。下文生成、上限、科技与替换规则指高额订单；普通订单与挑战订单见[订单种类](2026-11-24-order-types.md)。运行接入与画面验收状态见[反馈清单](../feedback-checklist.md)。

## 生成一张订单

1. **记住本周目入库的商品。** 取仓库的商品类别，现有目录为 P、PD、PL、PF、PM、PT。每种实际入过库的商品只登记一次，出货、消耗、库存降至零都保留资格。非生产来源实际入库的物品同样按商品类别判定；仅解锁配方或在货架上看见不算。原料与中间产物不进入候选池。
2. **由真实生产启动。** 本周目第一种商品真实完工入库时，先计入本批产值和候选记录，立即尝试一单，指定刚入库的商品。先前即使有非生产来源的商品入库，也不启动首单或替换它指定的商品。本次尝试无论成功与否，都从这次入库起累计有效经营时间。
3. **每满 30 分钟尝试一次。** 每次至多一单。未结束包括未接受和已接受锁定，二者所索商品都从候选池中排除。没有可选商品或额度不足则跳过本次，继续下一个 30 分钟周期。完成、放弃、升级或新商品入库都不会即时补发跳过的订单。
4. **检查两道上限。** 设上限为 `3 + 商路拓展等级`，范围 3 至 12。须同时满足「今日已生成单数 < 上限」和「当前未结束单数 < 上限」。首单也执行这两项检查。只有生成成功才计入当天已用名额，完成、放弃和过期均不退还。跨日保留的锁定单占并存名额，不占新一天的生成次数。

### 件数与固定报酬

取生成时的本轮真实完工总值 V（`productionValue`，包括原料、加工品和商品的真实完工），以及本单商品在该时刻的品质单价 U。按现有式样，目录基价 p、品质 q 对应 `U = p + (q − 1) × floor((p + 5) / 10)`。订单全程不乘市场行情。

- **所需件数 N** 为 `max(1, min(ceil(V / (2 × U)), ceil(C × H / 100)))`。前项用整数直接对整个分式向上取整，不能先把半数产值截去零头。C 为该商品本周目最高满负荷产出（`orders.capacity`，百分之一件／小时），H 为 8–24 的整小时数，按账户种子与订单序号（`order-hours`）抽取，读档不重抽。每单仅一个商品 ID。
- **最高产出 C** 取仓库每小时满负荷估算中该商品的产出（含全部已安排工位、等级与科技），在每次成功经营操作提交前及读档、导入时更新，只升不降，售庄清零。生产推进与离线结算不改变 C。
- **固定报酬 R** 先按生成时的订单溢价等级 L 计算每件报酬，四舍五入到整数金币后再乘所需件数，即 `R = N × floor((U × (50 + L) + 5) / 10)`。例如品质单价 101 金币，倍率 5.1，需 5 件，每件报酬 515 金币，订单共付 2,575 金币。
- 生成或成功替换时写入 N 和 R。已生成的订单，无论是否接受，后续产值、库存、品质、行情、科技以及存读档均不能改写这两个数。替换成功时用当时 V、新商品的 U 和当时 L 重新计算。

例如 V 为 4,001 金币、U 为 100 金币时，需要 21 件。零级报酬为 10,500 金币，生成后升到满级仍付 10,500 金币；相同 V、U 下满级新单才付 21,000 金币。

## 操作与结算

| 玩家操作 | 成功条件 | 成功后的记录 |
| --- | --- | --- |
| 接受 | 订单仍为未接受，库存可以不足 | 锁定这张订单，接受时不扣库存；跨日继续履约。 |
| 交付 | 已锁定，提交时可交库存够整单件数 | 手动一次扣齐，发固定报酬，结束订单。库存不足、重复点击、已失效的操作均不扣货、不记完成。 |
| 放弃 | 已锁定 | 订单作废，不发报酬、不给出货或完成进度，当日生成名额维持已用。 |
| 替换 | 未接受，当日替换次数还有余额，本周目累计候选至少 3 种，且排除原商品、其他全部现存订单商品后仍有候选 | 换为新商品及新快照，仍为未接受。成功才计一次替换，当日已生成单数和未结束单数均不变。无可选商品时保留原单和次数。 |

当日替换上限为 `1 + 客户协商等级`，范围 1 至 10。当天生成名额已满，仍可依上表替换。接受、交付、放弃、替换均以实际提交时的订单状态为准。

**交付库存判定。** 仓库的「加工保留量」只限制工坊自动取料，手动交单可以动用该部分库存。即使保留量等于或高于实存，只要整单货仍在库，就能亮点、启用按钮并交付。若有另一笔在途库存操作，须在提交时按最新已生效的库存及占用重核，同一件货不能扣两次；已失效或随离页释放的临时预留不能继续挡单。圆点、按钮与交付共用此判定。[仓库库存与保留量](../ui/pages/warehouse.md) · [行脚商预留的生效与释放](../ui/pages/merchant.md)

**一次交付是一笔出货。** 余额增加 R，出货件数（`stats.sold`）增加 N，本轮及累计实际经营收入（`stats.revenue`、`stats.lifetimeRevenue`）各增加 R，累计完成订单数增加 1。交付不增加本轮及终身生产总值或活动权益；订单款不套用普通仓库成交报价。扣库存、结单、发钱、统计、任务奖励与领取回执同一事务提交。保存失败时不能部分入账，重试和读档不能重复领取。

**任务「完成1件订单」。** 在主线「烤出乡村面包」（`firstBread`）之后、「第一次出货」（`firstSale`）之前插入独立任务，条件为累计成功交付至少一单，条件文案为「成功交付至少 1 件订单」，任务图标为 `menu-orders`，目的地为订单中心。排列只影响展示；同一次交付可同时完成这两项待完成的任务。「第一次出货」的旧条件文案仅提到仓库，实装时改为「通过仓库或订单出货至少 1 件」。其 ID、既有回执、金币和 1 高级点奖励保留，按同一回执只发一次。若此前已在仓库首出货，交单只结算尚未领取的任务。首次经仓库出货也无须先交单。任务奖金不算订单款、出货收入或产值。

订单款属于经营收入；行脚商按渠道记录的普通仓库分级销售额和直接卖给行脚商的金额沿用各自成交入口。管理员送礼额度的现有文字指定普通仓库实际销售额，但实际读取本轮经营收入；实施时须区分这两个口径以保留既有送礼规则。[行脚商交易](../ui/pages/merchant.md) · [管理员送礼](2026-11-18-manager-relationships.md)

## 跨天、出售与离线

| 事件 | 订单与候选 | 额度和时间 |
| --- | --- | --- |
| 设备当地自然日切换 | 未接受单全部过期；锁定单及其快照继续有效，保留本周目入库记录 | 刷新当日生成与替换已用次数。保持已启动的半小时进度。 |
| 确认出售庄园成功 | 清空全部未接受单和锁定单、清空本周目候选 | 保留当日已用两种额度，停止原计时并清除余量。新周目首件商品真实生产入库才重新尝试首单并从零计时。出售预览或取消时不执行。 |
| 离线返回 | 依保存的代管时长上限截取有效经营时间。在这段时间内，按时间顺序处理真实生产入库、当地日切换和各次应生成订单，分别读取各事件当时的状态 | 代管截止后没有生产或半小时尝试。回到设备当前当地日仍要处理已经发生的换日，过期未接受单、保留锁定单。和原有效日规则一样，时钟回拨不能再次刷新已用额度，回访不得重算已消费时段。 |

离线举例：距下一次尝试还差 10 分钟，期间第 8 分钟有商品完工，第 20 分钟再完工。第 10 分钟的订单可使用第 8 分钟已入库的商品和累计产值，不能读取第 20 分钟的完工结果。若两次完工间跨当地午夜，还须按订单所属自然日消耗额度。现有行情离线取回访日的规则仍只适用于行情。

**同一时刻先换日，再完成全部生产入库，最后尝试生成订单。** 当时全部真实完工的产值都进入 V。若多种商品在该时刻同时成为本周目首次商品完工，按稳定的工位顺序取首件，首单指定该商品；在线推进、离线补算和读档续算采用同一顺序。

| --- | ---: | --- | --- |

## 订单中心、提示与管理员

订单列表沿用田地的「缩小／放大」切换普通与紧凑视图，商品正下方显示浅蓝色「未接受」、金色「待备货」或绿色「可交付」。整张订单卡都可点击，一次打开详情，无须点箭头。详情内直接展示生产链树，拖动平移与缩放同科研树，节点以指针点选。原料在上、订单商品在下，按各级实际生产配方连接，跨分支共用的材料只显示一个节点并保留全部连线。研发前置和研发耗材不作为生产原料。[订单页操作](../ui/pages/orders.md)

订单页使用独立岗位背景。男女各有四表情立绘以及一张独立构思的完整开屏图。开屏从人物设定出发，用具体事件、人物当时的动作与表情呈现性格；与岗位胸像分别登记。共 12 个岗位、24 张开屏 CG，开屏只抽取各岗位已选形象。新档订单岗位默认男性（全员六男六女）；旧档缺该岗位时补入男性，其他岗位已选形象保留。

- **地图入口和建筑。** 大地图主路右侧、田地下方与鱼塘上方之间的空地设「订单中心」（`center` [0.5017, 0.9955]，`widthRatio` 0.258），建筑和对应门牌进入同一订单页。保持邻近建筑和地图滚动的命中范围可用。建筑主体与实际要运动的部件分别绘制、叠放，在运行地图可见时能看到局部运动。动件不参与经营结算。
- **订单详情。** 每单显示商品名称、所需件数、当前库存、固定报酬。未接受时提供接受、符合条件时可替换；锁定后提供交付、放弃。放弃先经确认弹窗；交付成功浮现「已交付 +报酬 金币」，替换成功浮现「已替换」。交付就绪统一判定为「存在至少一张已接受且库存足够一次交齐的订单」。该状态以圆点体现在地图订单中心门牌右上角和右上菜单「订单中心」格子右上角（与回礼提醒合并为同一圆点），订单中心页标题旁不显示；交付、库存增减、放弃、出售及读档后按当前状态重判。交一单后如还有另一单可交，圆点持续点亮。
- **配方与品种选择。** 只从锁定单收集所索商品，标「订单商品」；按这些商品的实际生产配方向上递归至所有原料，经过的中间产物也标「订单原料」。多订单共用材料、同物品由多条路径到达，均按物品 ID 汇总同名标记。完成、放弃或售庄清单后，其他锁定单仍需要的标记继续保留。未接受、已过期和仅属研发耗材的物品不产生提示。
- **男女两位订单管理员。** 茜梨嘴上挑剔，手上细心，立绘中护着包裹整理绳结；奥林身穿赭金短外套和靛蓝马甲，身侧贴稳订单夹，另一手在胸肩前抬起放松的掌心示意客人慢慢说，肩胸、胯膝与双脚朝右前，头回转，双眼看向来人。二人分别使用各自全身原图导出的四表情。沿用岗位的资料、切换、好感、送礼、回礼和对白机制；切换形象沿用同一岗位关系。订单岗位按其他岗位的情境帮助机制，覆盖有可交付订单、有未接受订单、暂无订单三种情境，男女各一套符合人设的文案。开 Dialog 后原对白继续，收礼后立即逐字感谢，列表点资料不额外触发气泡或后台对白。[立绘与开屏来源](../assets.md#管理员场景-cg-开屏)
- **素材与画布验收。** 使用项目绘图技能生成建筑、动件、两位管理员和所需图标，由独立审图者分别审原画、导出成品与实际接入。先核对人物全身工作姿态、视线、身体朝向，再扩四表情。运行证据覆盖田地与鱼塘之间的实际位置、不同帧的部件运动、入口命中、角色切换与受礼、选择弹窗标记和库存圆点。HTML body 只承载一个 PixiJS 画布，竖屏铺满，横屏保持竖向比例。UI 只放操作所需短标签与状态。[大地图](../ui/pages/estate.md) · [管理员设置](2026-11-19-manager-expansion.md) · [素材规范](../assets.md)

## 存档与旧档

| 存续范围 | 须保存及恢复的数据 |
| --- | --- |
| 现存订单 | 可区分每张订单的标识、商品、未接受或锁定状态、固定件数与固定报酬。恢复锁定状态后重新判断库存提示。 |
| 本周目 | 候选商品 ID 集合（最高产出大于零的商品；旧档已登记的无产出商品保留但不入选）、各商品最高满负荷产出 `capacity`（缺字段按空表迁移，读档时按当前排产补记）、是否已由真实生产启动、下一次尝试所需的有效时间余量或等价进度。出售时一并清空。 |
| 当地日 | 已用生成名额、已用替换次数、所属有效日。售庄同日保留、实际换日刷新。 |
| 跨周目 | 累计成功交付单数，既有出货与累计经营收入、科技和所有任务领取回执。 |

件数、金币用 BigInt，持久化为十进制字符串。主档、备份恢复、导入导出与离线推进均应保真。

- **恢复候选资格。** 缺订单字段时，按仓库本周目已获得过的商品 ID（含保留的零库存行）和同一周目的行脚商真实完工记录 `merchant.produced` 取并集，仅收商品级物品。若较早档案两处均无证据，缺失的品项待下次实际入库再登记；跨轮累计产量、旧出货数量、已解锁配方均不足以证明本周目获得过。[仓库已获物品](../ui/pages/warehouse.md) · [行脚商周目记录](../ui/pages/merchant.md)
- **等待启动。** 缺订单字段的旧档以无单、计时未启动、新任务无回执开始。恢复出的候选记录不触发首单。升级后下一次**商品真实生产入库**时，仅对刚完工的商品尝试首单，再启动计时，此后正常从全部本周目候选中选取。
- **保留旧进度与可见性。** 原品项、批次、科技、权益、账户种子及已有任务回执保留。「科技全满」已有回执继续显示完成且已到账，未完成者按新定义判定。旧档阶段按原任务回执和实际完成的入门步骤判断。新订单任务单独待完成，不凭旧出货或旧引导阶段发放。对已经进入长期阶段的旧档，未完成列表同时保留原已开放的长期目标和新订单任务，不能因多一个未完成主线而重走入门或再次提示「长期目标已开放」。正常交付后可完成新任务、查看到账并保留其余回执；仍在入门期的旧档则按新增后的既有主线顺序展示。[任务页](../ui/pages/tasks.md) · [任务完成与回执](../../src/game/objectives.js)

## 实装核对清单

| 场景 | 验收结果 |
| --- | --- |
| 本周目商品 A 入库后售罄，B 已解锁但从未入库 | **A 零库存仍可抽到，B 不入池。** 只有非生产来源入库时，计时尚未启动。 |
| 旧档本轮 A 售罄但有仓库行或同轮完工记录，B 尚有库存，升级后首先实际完工的是 C | 恢复 A、B 的候选资格，读档无单且不计时。C 入库时首单只索 C；后续尝试 A、B 均可抽到，包括零库存的 A。 |
| 旧档已有长期目标且 `firstSale` 已到账，订单系统尚未启动 | 长期目标继续可见，新任务可见且待完成。交单后只领新增任务，不重开奖励、不重播长期阶段开放提示。 |
| 当日已出 3 单后同日售庄，新周目商品第一次完工 | **包括锁定单在内全部清空，生成与替换的已用次数均保留。** 首单尝试失败；计时重新起算。 |
| 两张旧锁定单跨日，基础上限 3；新日第一次生成成功 | 并存达到 3，当天仅用 1 个生成名额；再到时不出单。若释放一席，仅在下次正常尝试且有不同商品时才能生成。 |
| 仅两种候选，或三种候选全部被订单占用 | 均不能替换。出现可用的新商品后替换一次，原单商品和其他单商品都不能抽中，只扣一次替换。 |
| 同一订单生成后提品质、推进产值、升订单溢价，再接受、存读档、交付 | **件数与固定报酬沿用原单**。另一张未接受单成功替换后，以替换时的商品、品质、产值及科技定价。 |
| 第一笔出货经订单交付，并重试同一操作 | 只扣一次 N 件、收一次 R、记一次订单，同时结两项符合条件的任务，首出货点仅 1 点，生产总值与活动权益不动。 |
| 锁单需 8 件、实存 8 件，加工保留量 8 件，无其他生效中的占用 | 圆点亮，交付按钮可用；手动一次交齐后实存归零。提交前如另一起操作先行扣货，按最新实存重判且不重复扣货。 |
| 两单均可交，且部分材料共用 | 交其一后圆点仍亮、共用材料仍标记；放弃另一单后两处相应提示消失。 |
| 跨午夜离线且超过代管上限，快照中另有锁定单 | 有效时段内按先后及当地日分别计价、占额和过期；截止后的时间不生成订单。锁定单保留至交付、放弃或售庄。 |
| 当地午夜有两工位同时首次完工商品、另有原料完工 | 先处理新日，再将所有完工计入 V；首单占新日额度，索要按稳定工位顺序的第一种商品。 |
| 品质单价 105 金币，倍率 5.1，需交付 5 件 | 每件 535.5 金币四舍五入为 536 金币，固定报酬 2,680 金币。 |
