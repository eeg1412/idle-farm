## 规则

### 1. 标准完成时间（实时）

- 只在**未接受**订单显示（已接受仍显示「预计完成时间」，不变），列表卡与详情都显示，缩小视图不变。
- 设 P = `forecastHourlyProduction(world)` 中该商品的 `produced`（满负荷：所有安排了该商品的设施／工位满速，不计原料，百分之一件／小时）。P > 0 时显示 `ceil(件数 × 100 × 3,600,000 / P)` 毫秒，格式 `remainingTime`；P = 0（未研发、未安排或无此项）时显示红字「未安排生产」。三种订单一律按此计算。
- 新订单不再写入 `standardMs`；旧档订单已有的 `standardMs` 读档照常接受，不再用于显示。
- 标签右侧为圆形小「？」按钮。点击后订单管理员（茜梨／奥林，按 `managerStatus(world, 'orders').gender`）以现有「管理员钻出来说明」演出说一句：
  - 女（茜梨）：「这是把做这件货的工位全开起来、原料管够的时候，交齐要花的时间。真照这个数算，原料可得先替它备好哦。」
  - 男（奥林）：「标准完成时间，是做这件货的工位全部开工时，交齐所需的时间。原料不算在内，备料要留余量。」
- 列表卡上点「？」不打开订单详情。订单详情弹窗中点「？」时管理员出现在弹窗之上，说明结束后回到原弹窗，弹窗内容与滚动位置不变。

### 2. 挑战订单每次一张

- 每个满足挑战条件的检查点只生成 T1 = R(U)（规则同[订单平衡](2026-11-25-order-balance.md)第 3 节），不再生成 T2、T3。
- 替换照旧（共用每日替换次数，替换池规则不变）。接受挑战时撤回其他未接受挑战的逻辑保留（旧档多张时仍适用）。
- 旧档：读档校验继续接受至多 3 张未接受挑战单，保留到换日自然过期；已有挑战单时不生成新挑战（现行规则）。

### 3. 开拓奖金十倍

- 目标有研发缺口（g > 0）：P = 缺口集合研发成本之和 × 10。
- 目标已研发（g = 0）：P = `floor(目标研发成本 / 2) × 10`。
- `reward = N × 每件报酬 + P`、`bonus = P` 结构不变；倍率 `rewardRate` 不含奖金，不变。已存在订单不改写。

### 4. 挑战订单收益显示

- 列表卡与详情：「固定报酬」显示 `reward − (bonus ?? 0)`（带倍率标记，不变）；其下「开拓奖金 x 金币」（bonus > 0 时）、「时空胶囊 x 个」（capsules > 0 时）。非挑战订单不变。
