# 管理员与经营记录

## 页面与入口

经营页按顺序显示管理员管理、统计、出售庄园历史、图鉴、出售庄园。沿用现有导航卡样式，整张卡可点击。新增页保留统一页头、返回与菜单。五个经营子页均放经营管理员横幅，默认介绍当前页用途，不重复页面标题。

| 页面 | URL | 经营卡说明 | 新绘图标 |
| --- | --- | --- | --- |
| 管理员管理 | `#/managers` | 查看管理员、送礼与切换形象 | `manager-directory` |
| 统计 | `#/statistics` | 查看产出、收入与经营进度 | `statistics` |
| 出售庄园历史 | `#/farm-sale-history` | 查看历次出售时间与产值 | `sale-history` |

三个新页注册到既有路由和菜单，标准上一级为经营。资料、选礼、选量各自保存父层。关闭、Escape 与浏览器返回逐层退回，恢复来源列表滚动和筛选。菜单进入新页时也使用经营父级。管理员管理有可领回礼时，其经营卡与菜单入口显示一个右上角红点。

## 立绘与反馈

页面横幅恢复原窄幅胸像的视觉大小、脸部位置和底边。田地女性和经营男性优先对照修正，所有角色使用同一登记方式。以源图脸部锚点定位，立绘左侧超出屏幕可以自然裁切；禁止再为容纳帽檐或道具而缩小人物、向右推脸。气泡和图标仍在人物上层，脸部应可辨识。资料卡内继续等比铺满固定胸像框，允许框内裁切。

送礼成功不显示 Toast。其他 Toast（包括领取回礼）使用既有顶部位置。关闭图形改为白色叉，约 16–18 逻辑像素，不画独立按钮底板；透明命中区保持至少 44×44。点叉只关闭当时那条提示，文字区照常允许穿透，自动消失时长保留。

## 姓名、对白与表情

`src/view/manager-dialogue.js` 为 11 个岗位、女男各一套写入稳定的虚构姓名。姓名采用短音译名，不加姓氏、国籍、称号或现实国家背景。22 个姓名取对白作者本次定稿，资料与管理列表读取同一 `name` 字段，岗位单列。切换形象立即同步姓名、性格、立绘和台词，关系账仍跟随岗位。

每套角色提供三组独立短句，语气符合[原人物设定](../Pixel-Characters-Complete-Pack/角色设定与性格.md)。每组恰好 10 句，组内不得靠换一个语气词凑数。

| 字段 | 触发 | 表情 |
| --- | --- | --- |
| `hello` | 进入岗位页且没有帮助时，随机一句 | `smile` |
| `thanks` | 成功收到普通礼物，随机一句 | `smile` |
| `wantedThanks` | 成功收到当日心愿礼物，随机一句 | `happy` |

合计 660 句。原有帮助、待领回礼和领取后的短句继续使用，表情为微笑，实际缺料提示可用已有不高兴表情。只有成功收到心愿礼物触发高兴。送礼采用成功动作返回的 `wanted` 判断，不能在成交后重新读可能已变化的心愿名单。

随机选择发生在进入或成功事件当刻，已选句子连同表情进入现有对白队列。进入岗位页有帮助时直接显示帮助，无帮助时才显示日常。感谢立即抢占并在结束后恢复适用的基础对白。渲染、自动保存、生产更新和纹理到达不再抽句，也不重置打字或三秒停留。返回原资料和关闭数量弹窗不额外问好。保留现有逐字、FC 音效、提示红字与完成后至少三秒的队列规则。切换角色后旧角色未播放对白作废。

送礼成功后返回原横幅或管理卡片并立即感谢，不显示成功 Toast；每次只运行当前可见说话者。资料不再有送礼入口或对白。领取回礼继续以顶部 Toast 显示实际收到的物品与件数。

## 管理员管理

按任务、经营、田地、畜牧、鱼池、矿洞、加工、精制、仓库、研究、行脚商顺序纵向排列 11 张卡。行脚商尚未开摊也能管理关系。没有性别筛选或单独的关系副本。

每卡左侧是框内胸像，右侧依次为姓名、岗位、好感等级和下一等级进度；满级显示已满级。底部并排放资料、送礼、切换形象，三者均使用现有专用图标与短标签，触控区至少 44×44。320 宽保持一张卡一行。存在可领回礼时在资料入口右上角点亮红点，资料中显示现有领取操作。没有回复时不预留气泡高度，信息与按钮紧凑衔接；感谢期间才显示卡内回复。

资料和送礼流程提取为按岗位 ID 调用的共用入口，禁止复制第二套送礼计算。列表、岗位页和资料必须共享好感、心愿、每日上限、送礼额度、真实产值额度和回礼池。切换后保存成功再更新画面。列表采用既有可见区域加载，离屏卡片不播放对白音效或加载所有表情。

## 统计

采用现在、累计两个等宽页签。默认现在，切换时回到页首。只显示下面可从现有状态准确取得的值，不新增未经记录的日收入、净利润、投入成本或累计行脚商收入。

| 页签与分组 | 玩家标签 | 精确来源 |
| --- | --- | --- |
| 现在·产销 | 出售前累计产值 | `world.productionValue` |
| 现在·产销 | 仓库销售收入 | `world.stats.revenue` |
| 现在·产销 | 行脚商销售收入 | `world.merchant.directSales` |
| 现在·产销 | 库存估值 | 各物品现有库存乘当前 `marketUnitPrice` 后求和，包含保留库存 |
| 现在·产线 | 田地、畜牧、鱼池、矿洞、加工、精制 | 各类当前总数，并列生产中、待安排、缺材料的数量；仅加工及精制使用缺材料状态 |
| 累计 | 累计生产总值 | `world.lifetimeProductionValue`，已含当前经营产值，不再相加 |
| 累计 | 生产完成件数 | `world.stats.produced` 的数量求和 |
| 累计 | 仓库累计收入 | `world.stats.lifetimeRevenue` |
| 累计 | 仓库卖出件数 | `world.stats.sold` |
| 累计 | 出售庄园次数 | `world.completedRuns` |
| 累计 | 已研发物品 | 有效 `world.unlocked` 数量与当前目录总数 |
| 累计 | 品质提升次数 | `world.qualityDraws` |

用两列信息卡，左标签右数值。产线每类单卡，小状态行放在数字下，避免一行塞多个长标签。金额和件数按全局缩写规范，BigInt 计算，不转成浮点数后求和。当前行情、生产、卖出、领取和切换页面后使用新值，不为统计额外结算生产。库存估值与聚合只在相关状态变化后重算，不逐帧遍历全目录。

## 出售庄园历史

新状态 `world.farmSaleHistory` 初始为空数组。每项固定为 `{ run, soldAt, productionValue }`。`run` 是本次成功出售后的次数，`soldAt` 是成交当刻毫秒时间，`productionValue` 是清空前的 `world.productionValue`。次数和时间使用安全整数，产值为非负 BigInt。

动作层把本次已捕获的 `wallAt` 传给 `sellFarm`，纯游戏逻辑不读取真实时钟。既有直接调用省略可选时间时使用 `world.wallAnchorMs`，显式传入时间须为非负安全整数。报价核对成功后、清空生产总值前追加记录，与领取高级点、增加出售次数和重置生产同一事务提交。产值为零也记录。失败报价、失败保存和重复提交不新增历史。追加使用新数组，前台投影与离线结算不得改历史。

历史按出售次数倒序展示。每张卡只显示第几次出售、本地年月日时分和出售时产值。时间与产值分行，长金额按统一缩写适配。空列表显示「还没有出售记录。」。旧档缺少此字段时读为空数组，已有出售次数照常显示，不补造以前的时间或产值。历史保留全部有效记录，采用已有虚拟列表。

存档编解码、导入导出和备份恢复接入白名单。逐项验证字段、非负值与安全整数，`run` 严格递增且不大于 `completedRuns`，允许第一项从旧档后续次数开始。出售时间可因设备时钟回调而非递增，排序以次数为准。新记录只能在成功出售路径产生。

## 素材与接入

三枚图标必须由图片生成工具新绘，像素风与现有经营入口一致，分别表现人物名册、统计账表、带时间标记的庄园契书。背景透明，96 像素和菜单小尺寸均能辨认。原稿与导出记录位于 `assets/source/art/management-expansion/`，使用图为 `public/ui-icons/{manager-directory,statistics,sale-history}.webp`。保留提示词与裁切来源，独立审图通过再接线。

页面可集中在 `src/view/management-records.js`，由画布注册与经营入口调用；经营记录逻辑可用 `src/game/management-records.js`，存档和主动作接入仍走既有模块。姓名对白固定在 `manager-dialogue.js`。路由、菜单图标、返回父级、空状态和保存失败路径随新增页面一起交付。

## 验收

- 实际打开 320、390 宽画布，对照田地女性、经营男性及其余角色的面部锚点、像素大小、底边和遮挡。横幅允许左侧裁切，资料框保持胸像大小。
- 各 22 套数据均有姓名及三组各 10 句；实际进入、普通送礼、心愿送礼与返回验证随机时机和表情。无心愿礼物时不得出现高兴。
- 从经营和菜单进入三个新页，资料切换、列表／横幅→选礼→选量→成功／取消及浏览器返回均恢复正确父层。管理页切换、送礼和收礼与原岗位共享账目与预留库存。
- 核对统计零值、大数、行情变化和产线状态。累计产值不重复加当前值，行脚商收入不混入仓库累计收入。
- 成功出售一次只增加一条历史，记录成交前产值。零产值、过期报价、失败保存、跨标签修订冲突、旧档缺字段及导入导出均正确处理。
- 点按小白叉只关闭当前 Toast，顶部提示不遮住固定操作区；素材原图、发布图与实际菜单尺寸分别审阅。最终编译和 Sites 发布由主代理完成。
