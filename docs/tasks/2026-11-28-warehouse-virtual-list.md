# 仓库列表虚拟化

## 用户确认的需求

- 仓库页与仓库「批量管理」滚动卡顿。用户选择方案 1：仓库列表改为虚拟化，只建可见范围附近的卡片。

## 根因（静态分析，未实测）

- 每次产线完工，库存变化触发 `redraw()` 整页重建（`src/main.js` `paint` 在批次结束时刻重投影；`canvas-ui.js` 结构签名比较）。
- 仓库页使用 `scrollList`（`canvas-ui.js` 约 3699 行），为全部品项一次性建卡片（文字、徽章、按钮），滚动只切换显隐；品项多时每次重建新建数千个 Text。
- 批量管理弹窗叠在仓库页上，重建时底层仓库列表一起重建。

## 式样

- 仓库列表（放大、缩小两种视图）只为视口及上下缓冲范围内的行建立显示对象；滚动时建新进入的行、销毁离开的行。
- 画面、排序、筛选、卡片内容、按钮行为、键盘焦点、`focusIndex` 定位与滚动位置保持不变；滚动条长度按全部品项总高度计算。
- 其他使用 `scrollList` 的页面行为不变。
- 遵守 `docs/performance.md`：不新增按时钟重建，新建节点后标脏，图片沿用现有离屏加载。
