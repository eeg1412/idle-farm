同一购买事实可完成不同 ID 的支线与长期任务；两个购买门槛相同，奖励各为 300。所有任务按实际条件独立结算，不要求依次完成，也不要求正在显示对应阶段。支线沿用首次出货后出现的现有条件。

金额按当前门槛设置。基础畜牧场与鱼池起价为 600；P150 研发需 229752 金币和四种各 384 份中间产物；PT50 研发需 15589584 金币、PT49 等前置与九种实物投入。百级品质需持续投入物品和金币，完整图鉴覆盖全部目录。因此高阶品质、终阶商品与完整收藏获得较多奖励。收入奖励固定为目标的 5%，奖励本身不增加收入统计，不能触发自己的完成条件。研发依据见 [研发条件](../expansion/06-research.md)，生产依据见 [生产配方](../expansion/05-catalog.md)。

## 领取与事务

- 每个任务 ID 仅领取一次；无领取按钮，成功完成后自动发放。金额及合计都使用 BigInt，仅增加 `world.coins`。
- `world.taskRewards` 保存已领取的任务 ID 数组。余额与领取记录在同一份存档、同一 IndexedDB 写事务中提交；完成判断不读取跳过导览标志。
- `settleTaskRewards` 位于 `src/game`，只读取传入世界的真实任务进度，不依赖画布、DOM、存储或真实时钟。查询任务、展示投影、存档编码和解码都不发钱。
- 主线程每次 `commit` 先在私有草稿结算，再写存档；写入成功后才替换当前世界并提示本次奖励合计。保存失败或修订冲突不会将草稿余额、领取 ID 或成功提示泄漏到当前世界。
- 正常动作、前台自动保存、离线本地结算及 Worker 回传、离线汇总关闭、初始化与导出前保存共用此提交链。同一事件完成多个任务时按不同 ID 各领一次，之后再次结算不重领。
- 失败的经营动作不产生对应进度；其动作之前真实完成的生产和旧档补发仍可随该次正常保存一并提交。
- 任务奖励不修改 `stats.produced`、`stats.sold`、`stats.revenue`、`stats.lifetimeRevenue`、`productionValue` 或研发点。出货浮字使用实际售货收入差额，任务奖励另合并到成功 Toast。

## 旧档、周回与替换边界

- 旧档没有 `taskRewards` 时归一为 `[]`，按实际保存的累计产量、售货量、历史售货收入、购买数、解锁、品质和周回数识别已完成任务，首次成功提交时补发。不能证明的历史不推断，不以跳过导览当作完成。旧 schema 1 的 `everMadeIslandMilleCrepe` 仅通过原有迁移形成真实 P150 历史。
- 显式非数组、未知任务 ID、重复 ID 均按损坏记录拒绝，不能静默丢弃领取记录后重领。领取数组随导出、导入和备份恢复保存，读取或导入预检不发奖。
- 出售牧场保留领取 ID 与历史任务。首次交接完成 `newFarm` 后，在重置的 60 金币上加一次 2000，得到 2060；之后周回不重复发放该项，仍按原开局恢复 60。任务奖励不参与牧场估值与高级研发点计算。
- 导入采用来源存档完整替换：只在待导入草稿补发可证实且未领取任务，然后与替换一起原子提交，不叠加本地余额或本地领取池，也不额外计算导出后的离线收益。重复导入同一快照是恢复同一余额，不会累加奖励。
- 清除存档创建新世界，余额及领取池均重新开始；损坏记录重建同样使用新世界。恢复旧备份以后，在初始化的正常提交链处理其尚未领取且可证实的任务。
- 开发发放仍只改变其规定的解锁、永久科技和 1T 金币，不伪造生产、出货或收入。实际解锁满足配方收藏／完整图鉴条件时，可在独立开发存档中领取对应任务奖励；重复发放不会重领任务。正式存档与开发存档仍隔离。

## 页面与交付边界

任务卡显示本项奖励金币，已提交领取显示「已到账」。每项只发一次（页面不显示该说明），周回不重复领取；同时完成多个任务只合并一次奖励 Toast，无新增弹窗或音效。详见 [任务页面](../ui/pages/tasks.md)。

出售牧场的预览与确认面板共用 `farmDetails`，显示基础 60 金币；若即将完成首次周回且 `newFarm` 未领取，另列「首次经营交接另奖 2K 金币（仅一次）」。金额直接读取运行时的任务奖励表，已领取后不再显示额外奖励。
