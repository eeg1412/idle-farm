## 用户原要求与确认结果

用户原话：「现在订单分 高额 普通 挑战，三者分配不是很平衡。你有什么方案可以让玩家获取高利益的同时，不要拘泥于现有的配方，多尝试挑战订单？」PM 提出五项方案，用户确认：1 采纳（高额重复衰减与新品加成）、2 采纳（挑战倍率与开拓奖金、件数改口径）、3 采纳（挑战多选、可替换、放弃改冷却）、4 部分采纳（普通订单改小单快单；**不采纳**候选扩大到中间产物）、5 采纳（首次完成挑战附赠时空胶囊）。

PM 按方案原文定下的数值与细节（用户以「采纳」确认方案，未逐项指定）：衰减每次 0.1 倍、下限 0.5；新品加成 +2 倍、3 张；挑战倍率为高额倍率 +3；已研发目标的开拓奖金为一半；普通订单 H 为 1～4 小时、2 倍；放弃冷却 2 小时；胶囊每种商品 1,000 个。用户可再调整。

## 规则

本卡只改以下各条，其余沿用[订单中心](2026-11-22-order-center.md)与[订单种类](2026-11-24-order-types.md)。

### 1. 高额订单：同商品衰减与新品加成

- **交付计数。** `orders.delivered[商品ID]` 记本周目该商品**高额订单**成功交付次数 k。普通与挑战交付不计入。
- **新品加成。** 挑战订单成功交付时，`orders.boost[目标商品ID] = 3`（已有余量时重设为 3）。之后高额订单生成或替换到该商品时，若余量大于 0，本单倍率加 2 倍并把余量减 1；余量为 0 时删除该键。
- **每件报酬（十分位整数运算）。** 设订单溢价等级 L、加成 B（有余量为 20，否则 0）、衰减 d = `max(5, 10 − k)`，则每件 `floor((U × (50 + L + B) × d + 50) / 100)`，再乘件数。k=0 且 B=0 时与现行 `floor((U × (50 + L) + 5) / 10)` 相等。
- 衰减和加成只在生成或替换时取值，已生成订单的件数与报酬不变。
- 出售庄园清空 `delivered` 与 `boost`。

### 2. 挑战订单：倍率、开拓奖励与件数

- **每件报酬** `floor((U目标 × (80 + L + 10g) + 5) / 10)`，g 为生成或替换时目标的研发缺口（见第 3 节，用户 2026-11-25 确认：每差一步研发加 1 倍），U目标 仍取目录基价（品质 1）。挑战不受衰减与新品加成影响。
- **开拓奖励（普通研发点）。** 生成或替换时按目标研发缺口 g 计 `pioneer = 100 + 100g`（g 为 0／1／2／3 时 100／200／300／400 普通研发点；取最小缺口且超过 3 时按同一公式），写入订单，之后不改写。交付时与挑战订单交付点数 200 相加，一起乘普通研发点倍率：发放 `(200 + pioneer) × (100 + 4L研) / 100`，L研 为普通研发点倍率等级；未加成合计 `300 + 100g`。开拓奖励不发金币。
- **件数** `N = max(1, min(ceil(V / (2 × U目标)), ceil(C0 × H / 100)))`。C0 为目标在一个 1 级工位、无科技下的每小时产出（百分之一件）：`round(output × 360,000,000 / durationMs)`，按目录 `output` 与 `durationMs` 计算，四舍五入同 `forecastHourlyProduction`。H 沿用 `order-hours` 按序号抽取的 8～24 整小时。不再使用基准商品产能。
- **金币报酬** `reward = N × 每件报酬`，订单的 `bonus` 为 0。已生成的旧挑战订单保留生成时的金币报酬（含当时的金币开拓奖金 `bonus`），`pioneer` 按 0，不补开拓奖励。
- **时空胶囊。** 生成时目标不在账号级 `world.challengeCapsuleItems` 中，则订单 `capsules = 1000`，否则为 0。交付时若 `capsules > 0` 且目标仍不在该集合：胶囊余额加 `capsules`，并把目标加入集合；同一事务提交。该集合出售庄园保留。

### 3. 挑战订单：多选、替换、冷却

- **基准**不变：本周目候选中 `durationMs` 最大者，同值取 ID 最小者。
- **选择规则 R(S)**：在集合 S 中，先在 `durationMs ≥ 基准` 的商品里取 `durationMs` 最小者；该组为空则取其余中 `durationMs` 最大者；同值取 ID 最小者。
- **研发距离（用户 2026-11-25 追加：「挑战任务会分配大量前置没有打通的物品，需要优化」）。** 商品的研发缺口 g = 该商品及其研发表 `requires` 递归闭包中不在 `world.unlocked` 的配方数（遇到已研发配方即停止向上展开）。已研发为 0，前置全部已研发、自身未研发为 1，还差一个前置为 2，还差两个前置为 3。
- **生成。** 设 U 为目录中未生产过的商品（不在本周目候选中），且只保留研发缺口不超过 `max(3, U 中最小缺口)` 的商品（`maxChallengeGap = 3`）：有缺口 0～3 的商品时只从这些商品中挑；没有时取缺口最小的一批（倍率按实际缺口加成）。依次取 T1 = R(U)、T2 = R(U − {T1})、T3 = R({u ∈ U − {T1, T2} : u 的 `kind` ≠ 基准的 `kind`})，空则略去。每个目标各生成一张挑战订单（各自序号，按 T1、T2、T3 顺序加入）。
- **触发（用户 2026-11-25 确认）。** 挑战订单不再等当天高额名额用完。每个 30 分钟检查点（含首单之后的全部定时检查点与胶囊加速）依次：① 高额额度未用完时尝试一张高额订单；② 满足挑战条件时生成挑战订单；③ 仅当**本检查点开始时**高额额度已用完，才尝试普通订单。挑战条件：本周目候选（`orders.capacity` 大于零）至少 1 种（用户 2026-11-28 确认由 3 种降为 1 种，见[挑战订单候选门槛](2026-11-28-challenge-one-candidate.md)）、当前无挑战订单、不在放弃冷却中、U 非空。首件商品入库触发的首单只生成高额订单。
- **并存。** 挑战订单未接受至多 3 张；接受其中一张时，其他未接受的挑战订单同时移除。已有挑战订单（未接受或已接受）时不生成新挑战。
- **替换。** 未接受的挑战订单可以替换，与高额、普通共用每日替换次数（`1 + 客户协商`），不要求「本周目候选至少 3 种」。替换池为 U（同样按研发缺口筛选）中排除当前全部挑战订单商品（含被替换的这张）且 `基准 ≤ durationMs ≤ 2 × 基准` 的商品，用 `chooseItem` 随机抽取；池为空时取 R(U − 当前挑战商品)；仍为空则不能替换。替换后按第 2 节以当时状态重算件数、报酬、开拓奖励和胶囊。
- **放弃冷却。** 放弃已接受的挑战订单后，`orders.challengeHoldUntilMs = 放弃时 clockMs + 7,200,000`。检查点时刻小于该值则不生成挑战订单。换日不清除冷却，出售庄园保留。取代原 `challengeHold` 布尔值。
- 换日时未接受的挑战订单照旧过期。

### 4. 普通订单：小单快单

- **件数** `N = max(1, ceil(C × H / 100))`，C 为该商品 `orders.capacity`，H 为 1～4 整小时，用 `accountRandom(accountSeed, 'normal-hours', 序号)` 抽取。不再使用 V 项。
- **每件报酬** `2 × U`，乘件数。不受订单溢价、衰减或新品加成影响。
- 候选仍只限本周目生产过的商品，不扩大到中间产物。并存 6 张、替换规则不变。

### 5. 时空胶囊加速订单检查点

用户原话：「需要时间才能生成的订单 允许使用 时空胶囊 加速」。PM 细化如下。

- **适用条件。** 订单计时已启动（`nextAttemptMs` 非空），且该检查点在当地日结束前，并且到点时确实能生成订单（即 `orderPlaceholders` 中最早一项为 `scheduled`，高额与「额度用完后挑战／普通」两种情形都算）。首单（等待首件商品）、`tomorrow`、`slotsFull`、`noCandidate`、`dailyLimit` 后无可生成项时不可加速。
- **费用。** 剩余时间 `due − clockMs` 按分钟向上取整，每分钟 100 个胶囊（与建筑快进同价），最多 30 分钟 3,000 个。持有不足时不可加速。
- **效果。** 扣胶囊后立即在 `clockMs` 执行一次该检查点的生成（与到点时同一套规则），`nextAttemptMs` 改为 `clockMs + 30 分钟`，即之后的检查点整体前移。世界时钟、生产与换日都不动；当天生成上限、并存上限照旧。扣胶囊与生成在同一事务提交。
- 一次操作只推进一个检查点，不提供数量选择。

### 存档与旧档

- `orders.delivered`、`orders.boost`：对象，键为商品 ID，值为正整数；缺字段按 `{}`。出售庄园清空。
- `orders.challengeHoldUntilMs`：`null` 或安全整数；旧档 `challengeHold`（任意值）迁移为 `null`。
- 挑战订单保存 `bonus`、`capsules`、`pioneer`（BigInt，十进制字符串持久化，≥0）；旧挑战订单缺字段按 0。其他种类订单不写这三个字段。
- `world.challengeCapsuleItems`：商品 ID 数组，账号级，缺字段按 `[]`，出售庄园保留。
- 校验：未接受挑战至多 3 张；有已接受挑战时不得同时存在其他挑战订单。不升级 `schemaVersion`。

## 接口约定（CORE 提供，UI 消费）

- 订单对象：`type: 'challenge'` 的订单含 `bonus: bigint`、`capsules: bigint`、`pioneer: bigint`；`reward` 为全部金币报酬（新单 `bonus` 为 0，旧单 `reward` 含 `bonus`）。`orderResearchReward(world, order)` 返回该单交付发放的普通研发点（含开拓奖励、已乘倍率）。
- `canReplaceOrder(world, id)` 对挑战订单按第 3 节返回。
- `orderPlaceholders` 形态不变，「能生成挑战」改按冷却与「无挑战订单」判定。
- 新导出 `challengeCooldownMs = 7_200_000`。
- 新导出 `orderRushCost(world): bigint | null`（不可加速时为 null）与 `rushOrder(world): boolean`（第 5 节，失败不改任何状态）。动作名 `rushOrder` 需在动作派发处注册（若派发表不在 CORE 文件内，CORE 报告位置由 PM 接入）。

## UI 要求

- 订单收益以一行图标显示（同任务卡奖励行）：金币（全部金币报酬）、普通研发点（交付点数与开拓奖励合计、已乘倍率）、时空胶囊（大于 0 时显示），见[订单中心](../ui/pages/orders.md)。
- 挑战未接受时提供「替换」按钮（`canReplaceOrder` 为真时）。
- 放弃确认灰字：挑战改为「订单作废，不发报酬，2 小时内不再有挑战订单。」其余不变。
- 高额订单衰减与新品加成不加说明文字。
- **报酬倍率标记（用户 2026-11-25 追加）。** 收益行金币数量后按行情标记样式显示箭头与倍率（值为 `rewardRate − 100`），列表卡与详情都显示。订单生成或替换时写入 `rewardRate`（倍率的百分位整数）：高额 `(50 + L + B) × d`（如 500 即 ×5、250 即 ×2.5），普通 200，挑战 `(80 + L + 10g) × 10`。之后不改写。旧档订单缺该字段时不显示标记。
- **标准完成时间（用户 2026-11-25 追加）。** 收益行下一行显示「标准完成时间」，列表卡与详情都显示。订单生成或替换时写入 `standardMs = ceil(件数 × 100 × 3,600,000 / C)`（Number），C 为生成时该商品产能（百分之一件／小时）：高额、普通取 `orders.capacity[商品]`，挑战取 C0（1 级工位无科技）。不计原料供给，之后不改写。C 为 0 或旧档缺字段时不显示该行。
- 订单页最早一张 `scheduled` 占位卡在 `orderRushCost` 非 null 时，在卡片框内倒计时下方显示按钮「加速 (胶囊图标 x)」（半角括号、小按钮、放大图标）（淡色）；胶囊不足时灰色。
- 页头「今日高额订单」上方显示时空胶囊持有数（图标 + 数量）。点击弹确认「消耗 x 个时空胶囊，立即生成订单？」，确认后提交 `rushOrder`。

## 必须保留

- 高额订单的件数公式、首单、计时、上限、离线逐事件、同刻顺序；k=0 且无加成时报酬与现行逐位相同。

- 已存在订单的件数与报酬不被改写。
